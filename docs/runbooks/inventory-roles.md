# มอบบทบาทโมดูลคลังพัสดุ

โมดูลคลังพัสดุรอบ 1 ใช้บทบาทสองชื่อ (ดู `CONTEXT.md` หมวด "คลังพัสดุ" และ `docs/superpowers/specs/2026-10-21-inventory-design.md`)

| บทบาท (`role.name`) | สิทธิ์ | ใช้ทำอะไร |
|---|---|---|
| `inventory-officer` | `inventory.item.manage`, `inventory.stock.receive`, `inventory.stock.read` | **เจ้าหน้าที่พัสดุ**: ดูแลทะเบียนวัสดุ หมวด ผู้ขาย และบาร์โค้ด บันทึกยอดยกมา รับเข้า ยกเลิกใบรับเข้า และพิมพ์ฉลาก QR |
| `inventory-supervisor` | `inventory.opening.certify`, `inventory.stock.read` | **หัวหน้างานพัสดุ**: รับรองหรือส่งกลับยอดยกมา และดูยอดคงเหลือ ได้รับแจ้งเมื่อมียอดยกมารอรับรอง |

- คลังมีแห่งเดียวสำหรับทั้งโรงพยาบาล จึงต้องมอบบทบาทแบบ `role_assignment.organization_id = NULL` เท่านั้น บทบาทที่ระบุหน่วยงานไม่ให้สิทธิ์ใดในโมดูลนี้
- ทุกการบันทึกตรวจสิทธิ์ที่ server หน้าจอซ่อนปุ่มเพื่อความสะดวกเท่านั้น

จนกว่าจะมีหน้ามอบบทบาท ให้ผู้ดูแลระบบมอบผ่านฐานข้อมูลหลังได้รับอนุมัติจากเจ้าของข้อมูล (งานพัสดุ) และบันทึกเหตุผลไว้ในใบงาน:

```sql
INSERT IGNORE INTO role (id, name, created_at) VALUES (UUID(), 'inventory-officer', UTC_TIMESTAMP());
INSERT INTO role_assignment (id, person_id, role_id, organization_id, created_at)
SELECT UUID(), '<person_id>', id, NULL, UTC_TIMESTAMP() FROM role WHERE name = 'inventory-officer';
```

ใช้คำสั่งเดียวกันกับ `inventory-supervisor` สิทธิ์มีผลในคำขอถัดไปเพราะ session โหลดบทบาทจากฐานข้อมูลทุกครั้ง

## ลำดับงานวันเปิดระบบ

1. เจ้าหน้าที่พัสดุสร้างหมวดวัสดุและทะเบียนวัสดุที่ **คลังพัสดุ › ทะเบียนวัสดุ** กำหนดหน่วยเบิก หน่วยซื้อ อัตราแปลง จุดสั่งซื้อ และการติดตามวันหมดอายุ แล้วผูกบาร์โค้ดผู้ผลิต
2. เพิ่มผู้ขายที่ **คลังพัสดุ › ผู้ขาย**
3. บันทึกยอดยกมาที่ **คลังพัสดุ › ยอดยกมา** ด้วยการสแกนหรือเลือกวัสดุ กรอกจำนวน ราคาต่อหน่วย และวันหมดอายุ แล้วกด "ส่งรับรอง"
4. หัวหน้างานพัสดุตรวจแล้วกด "รับรองยอดยกมา" หรือ "ส่งกลับแก้ไข" พร้อมเหตุผล
5. หลังรับรองแล้ว พิมพ์ฉลาก QR ของยอดยกมาติดของในคลัง และเริ่มรับเข้าที่ **คลังพัสดุ › รับเข้า** ได้

ยอดยกมาที่รับรองแล้วแก้ไขไม่ได้ ยอดที่ผิดต้องแก้ด้วยการปรับยอด ซึ่งจะมาในรอบที่ 3

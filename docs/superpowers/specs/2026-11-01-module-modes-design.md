# โหมดโมดูล (เปิด/ปิด/พัฒนา) และบทบาทผู้ทดสอบ — design

วันที่: 2026-11-01 · branch `claude/module-modes` · ต่อจาก `2026-11-01-admin-module-design.md`

## คำขอผู้ใช้

- การควบคุมโมดูลมี 3 โหมด: เปิด / ปิด / พัฒนา
- ไอคอนโมดูลในโหมดพัฒนาต้องมีสัญลักษณ์เด่นชัด
- เพิ่มบทบาท **ผู้ทดสอบ (tester)** ในการกำหนดสิทธิของแต่ละโมดูล
- โหมดพัฒนาเห็นได้เฉพาะ admin / ผู้จัดการ / ผู้ทดสอบของโมดูลนั้น
- เปลี่ยน "ภาพรวม" เป็น "หน้าหลัก"
- ไอคอนโมดูลบนหน้าหลักไม่แยกประเภท เรียงต่อกันตามสิทธิ์
- แถบ "โมดูลที่กำลังพัฒนา" (โมดูล planned) ด้านล่างแสดงเฉพาะ admin

## โหมดโมดูล

| โหมด | ค่าใน DB | ใครเห็น/ใช้ได้ |
|---|---|---|
| เปิด | `ON` | ทุกคนที่มีสิทธิ์ตามปกติ |
| พัฒนา | `DEVELOPMENT` | เฉพาะผู้ดูแลระบบ ผู้จัดการโมดูลนั้น และผู้ทดสอบโมดูลนั้น (ยังต้องผ่านสิทธิ์ปกติของแต่ละหน้า) |
| ปิด | `OFF` | ไม่มีใคร รวมผู้ดูแลระบบ (เหมือนเดิม) |

- Migration `0021_module_mode.sql` (additive): เพิ่มคอลัมน์ `admin_module_setting.mode VARCHAR(16) NOT NULL DEFAULT 'ON'` แล้วตั้ง `mode = 'OFF'` ให้แถวที่ `enabled = 0` ไม่มีแถว = `ON` เหมือนเดิม คอลัมน์ `enabled` ยังอยู่และเขียนให้ตรงกัน (`enabled = mode <> 'OFF'`) เพื่อให้โค้ดเก่าระหว่าง deploy อ่านได้
- `AdminService.setModuleMode(actor, code, mode)` เขียนแถวและ audit `admin.module.mode_changed` metadata `{ moduleCode, fromMode, toMode }` ใน transaction เดียว (อ่านโหมดเดิมแบบ `FOR UPDATE`) เปลี่ยนเป็นโหมดเดิมไม่บันทึก audit (`changed: false`)
- `admin` ล็อกไว้ที่ `ON` (`MODULE_LOCKED`)
- API `PUT /api/admin/modules/:code` รับ `{ mode: 'ON' | 'OFF' | 'DEVELOPMENT' }` เฉพาะ admin (ตรวจที่ server)
- หน้าตั้งค่าโปรแกรม: segmented control 3 ปุ่ม (เปิด / พัฒนา / ปิด) ต่อโมดูล กดแล้วยืนยันใน `ActionDialog` บอกโหมดเดิม → โหมดใหม่

### การบังคับที่ server

`apps/web/src/proxy.ts` อ่านโหมดของทุกโมดูล ถ้า path เป็นของโมดูลที่ `OFF` → ปฏิเสธทุกคน; ถ้า `DEVELOPMENT` → อ่าน session (เฉพาะกรณีนี้) และปฏิเสธถ้า `canUseModule(subject, code, mode)` เป็นเท็จ — หน้าได้หน้า "โมดูลนี้ปิดใช้งาน" 403, API ได้ `{ error: 'module_disabled' }` 403 เหมือนโหมดปิด (ไม่บอกคนทั่วไปว่าโมดูลกำลังพัฒนา) `ModuleLayout` ตรวจซ้ำอีกชั้น เมนูและหน้าหลักซ่อนด้วยฟังก์ชันเดียวกัน (`usableModules`)

## บทบาทผู้ทดสอบ — การตัดสินใจ

เลือก **role แยกต่อโมดูล** ชื่อ `<module-code>-tester` (เช่น `fleet-tester`, `official-travel-tester`) แทน role กลาง `module-tester` ที่จำกัดด้วยโมดูล เหตุผล:

- `role_assignment` มีขอบเขตได้แค่ `organization_id` ไม่มีคอลัมน์โมดูล role กลางจะต้องเพิ่มคอลัมน์และแก้ทุกจุดที่อ่าน role — role ต่อโมดูลใช้ตาราง/กำหนดสิทธิ/audit `roleName` เดิมได้ทันที
- ตรงกับรูปแบบ `moduleManagerRoles` (หนึ่ง role ต่อโมดูล) — `moduleTesterRoles` ใน `packages/core/src/admin/module-managers.ts`
- ใช้รหัสโมดูลเต็มเป็นคำนำหน้าเพื่อเดาได้ทันทีและไม่ชนกับ role เดิม

มี role ผู้ทดสอบสำหรับทุกโมดูล live ยกเว้น `admin` (รายการใน `testerModuleCodes` ใน `@backoffice/contracts`) role ผู้ทดสอบ **ไม่ให้ permission ใด ๆ** (`roleGrantsPermission` ไม่รู้จัก) จึงได้แค่สิทธิ์ผู้ใช้ทั่วไปของโมดูล ใช้เพียงผ่านด่านโหมดพัฒนา หนึ่งคนถือได้หลาย role (ผู้จัดการ + ผู้ทดสอบ + admin ฯลฯ)

UI: หน้ากำหนดสิทธิมีกลุ่ม checkbox "ผู้ทดสอบ" ต่อจากผู้จัดการ; popup ของโมดูลในตั้งค่าโปรแกรมมีรายชื่อผู้ทดสอบ เพิ่ม/ลบได้ (FormDialog + ActionDialog) เหมือนผู้จัดการ

## หน้าหลัก

- ป้าย "ภาพรวม" → "หน้าหลัก" (คีย์ `dashboard`)
- launcher เป็น grid เดียวเรียงตามลำดับใน `moduleRegistry` ไม่มีหัวข้อกลุ่ม (`group` ถูกลบจาก `ModuleEntry`)
- โมดูลโหมดพัฒนา: ป้าย "กำลังพัฒนา" (ข้อความ) + ขอบเส้นประลายทางสีเหลืองอำพันบนการ์ด และป้ายเล็ก "พัฒนา" ในเมนูด้านข้าง
- ส่วน "โมดูลที่กำลังพัฒนา" (planned) แสดงเฉพาะผู้ดูแลระบบ (`visibleModules` ตัด planned ออกสำหรับคนอื่น)

## นอกขอบเขต

ผู้ทดสอบแบบจำกัดหน่วยงาน, โหมดพัฒนาของโมดูล planned, การแจ้งเตือนเมื่อเปลี่ยนโหมด

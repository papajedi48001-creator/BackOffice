# ภาพรวมห้องประชุม (ปฏิทินรายเดือน) และแถบเมนูโมดูล

วันที่: 2026-11-02 · ผู้ขอ: wasan · ต่อจาก `2026-10-21-room-booking-design.md`

## สิ่งที่ผู้ใช้ขอ

> ทำสวยๆ ขึ้น และเพิ่มหน้า dashboard ในโมดูลจองห้องประชุม ทำเหมือนปฏิทินสวยๆ ว่าวันนี้วันนั้นในอดีตและอนาคตมีการจองจากใคร และสามารถคลิกเพื่อแสดงรายละเอียดเพิ่มเติมได้

## การตัดสินใจ (ตีความที่น่าจะใช่ที่สุด และบอกผู้ใช้แล้ว)

| เรื่อง | เลือก |
|---|---|
| รูปแบบ dashboard | ปฏิทินรายเดือน จันทร์–อาทิตย์ ย้อนดูอดีตและเลื่อนไปอนาคตทีละเดือน มีปุ่ม "เดือนนี้" |
| สิ่งที่แสดงในช่องวัน | เวลา ห้อง หัวข้อ ผู้จอง สูงสุด 3 รายการ เกินจากนั้นเป็นลิงก์ "+N รายการ" ไปมุมมองรายวัน |
| การจองที่แสดง | รออนุมัติ และอนุมัติแล้ว (วันที่ยังไม่คืน) เหมือนปฏิทินเดิม ไม่แสดงที่ยกเลิก/ไม่อนุมัติ |
| คลิกดูรายละเอียด | popup (native `<dialog>`) แสดงข้อมูลสาธารณะตาม decision #8: เลขอ้างอิง ห้อง/ที่ตั้ง วันที่ เวลา หัวข้อ ผู้จอง หน่วยงาน สถานะ ลิงก์ "เปิดหน้ารายละเอียด" แสดงเฉพาะผู้จองและผู้อนุมัติในขอบเขต (หน้า detail ตรวจสิทธิ์ซ้ำ) รายการเสริมและเหตุผลยังไม่แสดงใน popup |
| ตัวเลขสรุปด้านบน | การจองวันนี้, การจองในเดือนนี้, ห้องที่เปิดให้จอง, รออนุมัติ (เฉพาะผู้อนุมัติ) |
| สถานะ | ข้อความ + รูปแบบเส้น (รออนุมัติ = ขอบประ) ไม่ใช้สีอย่างเดียว ใช้ token สีโมดูล ไม่เพิ่ม hex |
| วันในอดีต | จางลง แต่ยังคลิกดูได้ วันนี้มีกรอบเน้น |
| มือถือ | กริดเปลี่ยนเป็นรายการตามวัน (ซ่อนวันว่าง) |
| "สวยขึ้น" | โมดูลใช้ `ModuleLayout` + แถบเมนูย่อยแบบโมดูลอื่น (ภาพรวม · ปฏิทินรายสัปดาห์ · จองห้อง · การจองของฉัน · รออนุมัติ (badge) · จัดการห้อง) สี `room-booking` และหัวหน้าเพจที่สะอาดขึ้น |

## เส้นทาง

- `/rooms` → `ModuleIndex` เปิดส่วนแรกที่เห็น (ภาพรวม)
- `/rooms/dashboard?month=YYYY-MM&roomId=` ใหม่
- `/rooms/calendar?week=|view=day&date=` ย้ายจาก `/rooms` เดิม

## ข้อมูล

`RoomBookingQueries.calendarForViewer(from, to, actor, roomId?)` คืน entry ของปฏิทินพร้อม `roomPlace` และ `canOpen` (ผู้จอง หรือผู้มี `room.booking.decide` ในหน่วยงานเจ้าของห้อง) ไม่ส่ง personId ของผู้จองไปที่ browser

## นอกขอบเขต

การลากเพื่อจอง, สีแยกตามห้อง, ส่งออกปฏิทิน

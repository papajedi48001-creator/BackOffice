# ระบบอุบัติเหตุหมู่ (Mass Casualty Incident) — design

Request (wasan, 2026-11-10): โมดูลรับมือเหตุอุบัติเหตุหมู่ มีหน้า login ให้เจ้าหน้าที่รายงานตัว เมนูอุบัติเหตุฉุกเฉิน ผู้ดูแลกำหนดบทบาทและตั้งค่าการจัดคนไปจุด (ER/OPD/IPD) และ dashboard สาธารณะ (ไม่ต้อง login) แสดงยอดผู้ป่วยตามสี triage และสถานะ. ใช้ login ของ BackOffice ไปก่อนระหว่างรอ SSO Provider ID. Superpowers brainstorming invoked through the Skill tool; requirements were grilled one question at a time (12 decisions, log: `/mnt/project-files/mass-casualty/decisions.md`).

## เป้าหมายและเกณฑ์สำเร็จ

- ผู้บัญชาการเหตุประกาศเปิดเหตุได้ในไม่กี่คลิก และเรียกคนผ่าน LINE + กระดิ่ง
- เจ้าหน้าที่สแกน QR → login → กด "รายงานตัว" แล้วรู้ทันทีว่าต้องไปจุดไหน
- ผู้บันทึกลงทะเบียนผู้ป่วยได้เร็ว (เลขป้ายอัตโนมัติ + สี + จุด) แล้วเติมชื่อทีหลัง
- ญาติและประชาชนเห็นยอดผู้ป่วยตามสี/สถานะ และค้นชื่อผู้ป่วยที่ระบุชื่อแล้ว โดยไม่ต้อง login และไม่เห็นข้อมูลเกินจำเป็น
- ผู้บัญชาการพิมพ์/ส่งออกสรุปหลังปิดเหตุได้

| **การรายงานตัว** | เจ้าหน้าที่แจ้งว่ามาปฏิบัติงานในเหตุ มีเวลาเข้า เวลาออกเวร จุด บทบาทสั่งการ และสายวิชาชีพ | check-in |

## การตัดสินใจที่ตกลงแล้ว (สรุปจาก 12 ข้อ)

1. มี **เหตุ** เปิด/ปิดโดยผู้บัญชาการ เปิดได้ทีละเหตุ เหตุที่ปิดเป็นประวัติ
2. บันทึก **ผู้ป่วยรายคน**: เลขป้ายอัตโนมัติ + สี + จุด; ชื่อ นามสกุล เพศ อายุโดยประมาณ HN (ไม่บังคับ) ใส่ทีหลังได้
3. **สถานะผู้ป่วย** ค่าเริ่มต้น: รับเข้า/คัดกรอง, กำลังรักษา, รับไว้นอน รพ., ส่งต่อ (ระบุ รพ.ปลายทาง), กลับบ้านได้, เสียชีวิต
4. **บทบาทสั่งการ 4 แบบ** + **สายวิชาชีพ** แยกชั้น (ตารางสิทธิ์ด้านล่าง)
5. **กฎจัดคน** ตามสายวิชาชีพ; ไม่มีกฎ → "รอจัดจุด"
6. **สี triage 5 สี** ค่าเริ่มต้น; สีดำผูกกับสถานะเสียชีวิตสองทาง
7. **กระดานสาธารณะ** หน้าเดียว รีเฟรช 30 วินาที ยอด + รายชื่อชื่อย่อ + ค้นหา
8. **หน้าเข้า `/mci`** login แล้วกดรายงานตัว ทุกบัญชีบุคลากรที่ใช้งานอยู่รายงานตัวได้
9. **เรียกคน** ตอนเปิด/ปิดเหตุ ผ่าน LINE + กระดิ่ง เลือกทุกคนหรือบางสายวิชาชีพ
10. **ออกจากเวร** เองหรือโดยหัวหน้า; ปิดเหตุออกให้ทุกคน
11. **ซ้อมแผน** แยกจากเหตุจริงชัดทุกหน้า
12. รอบแรก **ไม่เชื่อม HOSxP**; สรุปและ CSV หลังปิดเหตุ

## ข้อมูล (migration `0032_mass_casualty.sql`, additive; Drizzle `packages/db/src/schema/mass-casualty.ts`)

ตั้งค่า (ไม่ผูกเหตุ):
- `mci_zone` (id, name, sort_order, is_active) seed: จุดคัดกรอง, ER, OPD, IPD
- `mci_triage_level` (id, code, name, description, color_hex, sort_order, is_deceased, is_active) seed 5 สี; `is_deceased` จริงได้แถวเดียว (สีดำ)
- `mci_patient_status` (id, code, name, sort_order, is_deceased, needs_destination, is_active) seed 6 สถานะ; `is_deceased` จริงได้แถวเดียว
- `mci_profession` (id, name, sort_order, is_active) seed 7 สาย
- `mci_profession_position` (profession_id, position_id) เติมสายวิชาชีพจากตำแหน่ง HR (`hr_position`)
- `mci_assignment_rule` (profession_id PK, zone_id)
- `mci_setting` (key PK, value) เช่น `public_contact_phone`

ต่อเหตุ:
- `mci_incident` (id, title, kind `REAL|DRILL`, status `OPEN|CLOSED`, location, occurred_at, opened_by, opened_at, closed_by, closed_at, patient_seq) ; ไม่มีสองแถว OPEN พร้อมกัน (ตรวจใน transaction ด้วย `SELECT … FOR UPDATE` บนแถว lock เดียว)
- `mci_responder` (id, incident_id, person_id, profession_id, zone_id null=รอจัดจุด, command_role `COMMANDER|ZONE_LEAD|RECORDER|STAFF`, checked_in_at, checked_out_at, checked_out_by) ; คนหนึ่งมีแถวที่ยังไม่ออกเวรได้แถวเดียวต่อเหตุ
- `mci_patient` (id, incident_id, tag_no, triage_level_id, status_id, zone_id, destination_hospital, first_name, last_name, gender, age_estimate, hn, public_hidden, created_by, created_at, updated_by, updated_at) unique (incident_id, tag_no)

เวลาเก็บ UTC แสดง Asia/Bangkok. ทุกการเปลี่ยน (เปิด/ปิดเหตุ, รายงานตัว, ออกเวร, ย้ายจุด, เปลี่ยนบทบาท, บันทึก/แก้ผู้ป่วย, ตั้งค่า) เขียน audit event และ outbox (ถ้ามี) ใน transaction เดียวกัน. audit metadata เก็บ id, เลขป้าย, รหัสสี/สถานะ ไม่เก็บชื่อผู้ป่วยหรือ HN.

## พฤติกรรม

### 1. หน้าเข้า `/mci`
- ยังไม่ login: แสดงแถบแดงชื่อเหตุที่เปิดอยู่ (หรือ "ขณะนี้ไม่มีเหตุ") + ฟอร์ม login เดิมของ BackOffice (`LocalSignInForm`) พร้อมพารามิเตอร์กลับมา `/mci` (path ภายในเท่านั้น ป้องกัน open redirect); ปุ่ม Provider ID ใช้ได้เมื่อ SSO พร้อม
- login แล้ว: เมนูอุบัติเหตุหมู่ แท็บย่อยตามสิทธิ์: **ภาพรวม** (ยอด+รายชื่อเต็ม), **ผู้ป่วย**, **กำลังคน**, **เหตุ** (เปิด/ปิด/ประวัติ), **ตั้งค่า**
- การ์ด "การปฏิบัติงานของฉัน": ยังไม่รายงานตัว → ปุ่มใหญ่ "รายงานตัว" (ปิดไว้ถ้าไม่มีเหตุ) กดแล้ว `ActionDialog` ยืนยันพร้อมเลือกสายวิชาชีพ (เติมจาก HR) → บันทึก → แสดง "ไปที่ ER" ใหญ่; รายงานตัวแล้ว → แสดงจุด บทบาท เวลาเข้า และปุ่ม "ออกจากเวร" (`ActionDialog`)
- ซ้อมแผน: แถบ "ซ้อมแผน ไม่ใช่เหตุจริง" ทุกหน้าของโมดูล

### 2. เหตุ
- เปิดเหตุ (`FormDialog`): ชื่อเหตุ, ชนิด (เหตุจริง/ซ้อมแผน), สถานที่, เวลาเกิดเหตุ (ค่าเริ่มต้น = ตอนนี้), ผู้รับแจ้ง (ทุกคน / เลือกสายวิชาชีพ / ไม่แจ้ง). มีเหตุเปิดอยู่แล้ว → 409 `INCIDENT_ALREADY_OPEN`
- ปิดเหตุ (`ActionDialog`): ออกเวรทุกคนที่ยังอยู่ (เวลาปิด) และแจ้งผู้ที่เคยรายงานตัวว่าปิดเหตุแล้ว
- ประวัติ: รายการเหตุที่ปิด กรองตามชนิด เปิดดูสรุปได้

### 3. การแจ้ง
- outbox `notification.in_app` ต่อคน + LINE ผ่าน `LineService` เดิม; `lineAlertModuleCodes` เพิ่ม `mass-casualty`
- ข้อความ: `[อุบัติเหตุหมู่] <ชื่อเหตุ> — รายงานตัวที่ <url>/mci` (ซ้อมแผนขึ้นต้น `[ซ้อมแผน]`) ไม่มีข้อมูลผู้ป่วย
- ผู้รับ: บุคลากร ACTIVE ที่มีบัญชี กรองตามสายวิชาชีพผ่าน `mci_profession_position`

### 4. การรายงานตัวและกำลังคน
- รายงานตัวซ้ำขณะยังไม่ออกเวร → คืนแถวเดิม (idempotent); หลังออกเวรรายงานตัวใหม่ได้ (แถวใหม่)
- จุดเริ่มต้น = `mci_assignment_rule` ของสายวิชาชีพ, ไม่มีกฎหรือจุดถูกปิด → รอจัดจุด
- หน้า **กำลังคน**: ตารางจุด × สายวิชาชีพ (จำนวนคนที่ยังไม่ออกเวร) + รายชื่อ; ปุ่มย้ายจุด / เปลี่ยนบทบาท / ออกเวรให้ เปิดใน `FormDialog`/`ActionDialog`; หัวหน้าจุดเห็นและทำได้เฉพาะจุดตัวเอง ("รอจัดจุด" จัดได้โดยผู้บัญชาการ)

### 5. ผู้ป่วย
- เพิ่มผู้ป่วย (`FormDialog`, ช่องที่ต้องกรอก: สี, จุด) → ได้เลขป้ายถัดไปจาก `patient_seq` (lock แถวเหตุ) แสดงเลขป้ายใหญ่ให้เขียนลงป้ายจริง; สถานะเริ่ม = สถานะแรกตามลำดับ (รับเข้า/คัดกรอง)
- แก้ไข (`FormDialog`): ทุกช่อง; สถานะ "ส่งต่อ" ต้องกรอก รพ.ปลายทาง; เลือกสีดำ → สถานะเสียชีวิต และกลับกัน; ออกจากสถานะเสียชีวิตต้องเลือกสีใหม่
- รายการ: ค้นด้วยเลขป้าย/ชื่อ/HN กรองตามสี สถานะ จุด
- เหตุที่ปิดแล้วแก้ผู้ป่วยไม่ได้ (409 `INCIDENT_CLOSED`)

### 6. กระดานสาธารณะ `/mci/board` และ `GET /api/mci/board`
- ไม่ต้อง login; API คืนเฉพาะ projection สาธารณะ สร้างฝั่ง server (`MciBoardQueries.publicBoard`):
  - เหตุ: ชื่อ ชนิด เวลาเกิดเหตุ, `updatedAt`
  - ยอดรวม, ยอดต่อสี (ชื่อ+สีจากตั้งค่า), ยอดต่อสถานะ (ไม่รวมสถานะเสียชีวิต — นับอยู่ในสีดำ)
  - รายชื่อ: เฉพาะผู้ป่วยที่มีชื่อ แสดงชื่อ-นามสกุลเต็ม (ผู้ใช้ขอเปลี่ยน 2026-11-12 เพื่อให้ญาติหาเจอ) และจุดที่อยู่ (ส่งต่อ → "ส่งต่อ <รพ.>"; กลับบ้าน → "กลับบ้านแล้ว"); **ผู้เสียชีวิต → "กรุณาติดต่อจุดประชาสัมพันธ์"**; ไม่มีสี HN อายุ เพศ หรือเลขป้าย
  - เบอร์จุดประชาสัมพันธ์
- ค้นหาชื่อทำบนข้อมูลที่โหลดแล้วฝั่ง client (รายชื่อมีแค่ชื่อย่อ)
- รีเฟรชทุก 30 วินาที (`Cache-Control: no-store`); ไม่มีเหตุเปิด → "ขณะนี้ไม่มีเหตุอุบัติเหตุหมู่" + เบอร์ประชาสัมพันธ์
- ออกแบบให้อ่านจากจอทีวี (ตัวเลขใหญ่, การ์ดสีพร้อมชื่อสีเป็นข้อความ ไม่สื่อด้วยสีอย่างเดียว) และมือถือ 390px
- `proxy.ts`: `/mci/board` และ `/api/mci/board` เปิดสาธารณะ แต่ยังถูก module gate (โหมดปิด/พัฒนา) เหมือนหน้าอื่น

### 7. ตั้งค่า (`/mci/settings`, ผู้ถือ `mci.command`)
แท็บ: จุดปฏิบัติงาน, สี triage, สถานะผู้ป่วย, สายวิชาชีพ (+ จับคู่ตำแหน่ง HR), กฎจัดคน, ข้อมูลติดต่อสาธารณะ. ทุกการเพิ่ม/แก้ใน `FormDialog`, ปิดใช้ใน `ActionDialog` (ปิดใช้แทนลบ เพื่อไม่ให้ประวัติเสีย). สีต้องผ่าน 3:1 กับพื้นขาว และมีชื่อเป็นข้อความเสมอ.

### 8. สรุปหลังปิดเหตุ
หน้า `/mci/incidents/[id]` สำหรับเหตุที่ปิด: ยอดต่อสี/สถานะ, รายชื่อผู้ป่วยเต็ม, เจ้าหน้าที่ + เวลาเข้า-ออก + ชั่วโมง; ปุ่มพิมพ์ (print CSS) และ CSV 2 ไฟล์ (ผู้ป่วย, เจ้าหน้าที่) ผ่านกลไก export เดิม (audit `data.export`).

## ความปลอดภัยและข้อมูลส่วนบุคคล
- กระดานสาธารณะใช้ projection แยก ไม่ reuse query ภายใน มี test ยืนยันว่าไม่มี HN สี เลขป้าย อายุ เพศ
- ข้อจำกัดที่รับทราบ: ข้อความ "กรุณาติดต่อจุดประชาสัมพันธ์" อาจทำให้ญาติเดาได้ จึงจะให้ผู้บัญชาการติ๊ก "ไม่เปิดเผยบนกระดาน" ให้ผู้ป่วยรายใดก็ได้ ซึ่งแสดงข้อความเดียวกัน (คอลัมน์ `mci_patient.public_hidden`)
- ไม่มีชื่อผู้ป่วย/HN ใน URL, log, audit metadata, notification, outbox payload
- API ทุกตัวตรวจสิทธิ์ฝั่ง server; UI ไม่ใช่ขอบเขตความปลอดภัย

## นอกขอบเขตรอบนี้
เชื่อม HOSxP, SSO Provider ID (ใช้เมื่อเธรด SSO เสร็จ), แผนที่/พิกัด, รูปผู้ป่วย, ติดตามรถพยาบาล, การทำงาน offline, เป้าจำนวนคนต่อจุด

## การทดสอบ
- unit (`packages/core/src/mass-casualty/*.test.ts`): `MciAccess` ตามตารางสิทธิ์, กฎจัดคน, การผูกสีดำ↔เสียชีวิต, `publicName`, projection สาธารณะ
- integration (MariaDB): เปิดเหตุซ้อน → 409, เลขป้ายไม่ซ้ำเมื่อบันทึกพร้อมกัน, รายงานตัว idempotent, ปิดเหตุออกเวรทุกคน, audit+outbox ใน transaction เดียว, migration
- web: route tests ของ API (401/403/409), `/mci/board` ไม่ต้อง login, popup ไม่ปิดด้วย Esc/คลิกนอก, ภาพหน้าจอ 1280/390

## กฎ popup และฟอร์มของโปรเจกต์
ทุก popup ใช้ `FormDialog`/`ActionDialog` ปิดได้จากปุ่มเท่านั้น (ไม่ปิดด้วย Esc หรือคลิกนอก). โมดูลนี้ไม่มีฟอร์มช่วงวันที่ จึงไม่มีจุดที่ใช้กฎ "วันสิ้นสุด = วันเริ่ม"; ถ้าเพิ่มในอนาคตต้องทำตามกฎนั้น.

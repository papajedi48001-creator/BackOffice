# แชตกับผู้ดูแลระบบ — design

วันที่ 2026-11-02 · ผู้ขอ: wasan

## สิ่งที่ผู้ใช้ขอ (ตามคำพูดผู้ใช้)

> chat box เพื่อให้ user โต้ตอบกับแอดมินได้ สามารถแนบรูปหรือภาพในคลิปบอร์ดได้ แต่ไม่สามารถส่งข้อความหากันระหว่าง user ได้
> เป็นการส่งข้อความหา admin อย่างเดียว รูปแบบเหมือน chat box ของ facebook ซึ่ง admin สามารถคุยกับ user หลายคนพร้อมกันได้
> user คุยกับแอดมินได้คนเดียว เพื่อแจ้งความต้องการหรือแนะนำการพัฒนาโปรแกรม

## ความเข้าใจและสมมติฐาน (ผู้ใช้แก้ได้)

- "แอดมิน" = **ผู้ดูแลระบบ** (role `admin` แบบทั้งโรงพยาบาล) ทุกคน ใช้กล่องรับข้อความร่วมกัน ผู้ดูแลระบบคนไหนตอบก็ได้ ผู้ใช้เห็นชื่อผู้ดูแลระบบที่ตอบ
- ผู้ใช้ทั่วไปหนึ่งคนมี **บทสนทนาเดียว** กับ "ผู้ดูแลระบบ" (ไม่ใช่กับผู้ดูแลระบบรายคน) ไม่มีทางเลือกผู้รับ จึงส่งหาผู้ใช้อื่นไม่ได้โดยโครงสร้าง
- ผู้ดูแลระบบไม่มีบทสนทนาของตัวเอง เห็นเป็นกล่องรับข้อความรวม และเปิดหน้าต่างแชตหลายคนพร้อมกันได้
- ผู้ดูแลระบบตอบได้เฉพาะบทสนทนาที่ผู้ใช้เริ่มแล้ว (ยังไม่มีการเริ่มแชตหาผู้ใช้ก่อน)
- ไม่มีการแก้ไข/ลบข้อความ ไม่มีการแจ้งเตือนในศูนย์การแจ้งเตือน (ใช้ตัวเลขบนปุ่มแชตแทน) ไม่มี real-time socket ใช้การดึงข้อมูลเป็นระยะ

## พฤติกรรม

### ปุ่มแชต (ทุกหน้าในระบบหลังเข้าสู่ระบบ)

ปุ่มกลมลอยมุมขวาล่าง ไอคอนฟองข้อความบนพื้นเขียวหัวเป็ด `--brand` ข้อความกำกับสำหรับ screen reader "แชตกับผู้ดูแลระบบ"
มีวงกลมตัวเลขสี alert เมื่อมีข้อความที่ยังไม่อ่าน (ผู้ใช้: ข้อความจากผู้ดูแลระบบที่ยังไม่อ่าน; ผู้ดูแลระบบ: จำนวนบทสนทนาที่มีข้อความใหม่จากผู้ใช้)
ตัวเลขอัปเดตทุก 30 วินาที

### ผู้ใช้ทั่วไป

กดปุ่ม → หน้าต่างแชตเปิดมุมขวาล่าง (กว้าง 340px สูง 460px; จอแคบกว่า 640px เต็มความกว้าง) หัวหน้าต่าง "ผู้ดูแลระบบ" ปุ่มย่อ (–) และปิด (×)
- ข้อความของตัวเองชิดขวาพื้นสีหลัก ข้อความผู้ดูแลระบบชิดซ้ายพื้นเทาอ่อน มีชื่อผู้ตอบและเวลา (เวลาไทย)
- ก่อนมีข้อความ แสดงคำแนะนำ "พิมพ์ความต้องการหรือข้อเสนอแนะการพัฒนาโปรแกรมถึงผู้ดูแลระบบ"
- ช่องพิมพ์: Enter ส่ง, Shift+Enter ขึ้นบรรทัดใหม่, ยาวไม่เกิน 2,000 ตัวอักษร
- ปุ่มแนบรูป (JPEG/PNG/WebP ไม่เกิน 10 MB) และ **วางรูปจากคลิปบอร์ด** (Ctrl+V ในช่องพิมพ์) แสดงตัวอย่างรูปพร้อมปุ่มเอาออกก่อนส่ง ส่งรูปพร้อมข้อความหรือรูปอย่างเดียวได้
- ถ้าเซิร์ฟเวอร์ยังไม่ได้ตั้งค่าที่เก็บไฟล์ ปุ่มแนบรูปไม่แสดงและการวางรูปขึ้นข้อความ "ระบบยังไม่เปิดให้แนบไฟล์"
- ขณะหน้าต่างเปิด ดึงข้อความใหม่ทุก 5 วินาทีและถือว่าอ่านแล้ว
- กดรูปเพื่อเปิดภาพเต็มในแท็บใหม่

### ผู้ดูแลระบบ

กดปุ่ม → แผงกล่องรับข้อความ: รายชื่อบทสนทนาเรียงข้อความล่าสุดก่อน แต่ละแถวมีชื่อ ตำแหน่ง ข้อความล่าสุดย่อ ("รูปภาพ" ถ้าเป็นรูป) เวลา และจุด/ตัวเลขยังไม่อ่าน
กดแถว → เปิดหน้าต่างแชตของผู้ใช้นั้นต่อกันจากขวาไปซ้ายแบบ Facebook เปิดพร้อมกันได้ 3 หน้าต่าง (เปิดอันที่ 4 อันเก่าสุดปิด) จอแคบแสดงทีละหน้าต่าง หน้าต่างแต่ละอันทำงานเหมือนของผู้ใช้ (แนบ/วางรูปได้) หัวหน้าต่างเป็นชื่อผู้ใช้
ข้อความของผู้ดูแลระบบทุกคนแสดงชิดขวา (ฝั่ง "เรา") พร้อมชื่อผู้ตอบ

### กฎ popup

หน้าต่างแชตและแผงกล่องรับข้อความไม่ใช่ modal ไม่บังการทำงานหน้าอื่น และปิดได้จากปุ่ม × / ย่อ เท่านั้น กด Esc หรือคลิกนอกหน้าต่างไม่ปิด

## ข้อมูล (migration `0026_support_chat.sql`)

- `support_conversation`: `id`, `person_id` (UNIQUE, FK person), `created_at`, `last_message_at`, `person_read_at` NULL, `admin_read_at` NULL — เวลาเป็น UTC `DATETIME(3)`
- `support_message`: `id`, `conversation_id` (FK), `sender_person_id` (FK person), `from_admin` TINYINT, `body` TEXT NULL, `attachment_id` (FK attachment) NULL, `created_at` `DATETIME(3)`; index `(conversation_id, created_at)`
- ยังไม่อ่าน (ผู้ใช้) = ข้อความ `from_admin = 1` ที่ใหม่กว่า `person_read_at`; (ผู้ดูแลระบบ) = บทสนทนาที่มีข้อความ `from_admin = 0` ใหม่กว่า `admin_read_at`

## เซิร์ฟเวอร์

`packages/core/src/support-chat/support-chat-service.ts` (`SupportChatService`) — ตรวจสิทธิ์ทุกครั้งในเซิร์ฟเวอร์:
- `sendAsPerson(subject, input)` — สร้างบทสนทนาของตัวเองถ้ายังไม่มี แล้วเพิ่มข้อความ ผู้ส่งเป็นได้แค่เจ้าของบทสนทนา
- `sendAsAdmin(subject, conversationId, input)` — `isAdmin` เท่านั้น
- `input = { body?: string; attachmentId?: string }` ต้องมีอย่างน้อยหนึ่งอย่าง; body ตัดช่องว่าง ยาว ≤ 2,000; attachment ต้องเป็นไฟล์ที่ผู้ส่งอัปโหลดเองและเป็นรูป (jpeg/png/webp)
- ข้อความ + อัปเดต `last_message_at` + บันทึกการตรวจสอบ `support.message.sent` (metadata เฉพาะ `conversationId`, `hasAttachment` ไม่มีเนื้อความ) อยู่ใน transaction เดียว
- `markRead…`, `myConversation`, `adminInbox`, `adminConversation`, `unreadCount`
- `AttachmentAccess` เพิ่มกฎ: รูปในแชตเปิดได้โดยเจ้าของบทสนทนาและผู้ดูแลระบบ

API (`apps/web/src/app/api/support-chat/…`):
- `GET /summary` → `{ unread }`
- `GET /mine` → ข้อความ 200 ล่าสุดของตัวเอง; `POST /mine/messages`; `POST /mine/read`
- `GET /conversations` (admin) ; `GET /conversations/[id]` (admin); `POST /conversations/[id]/messages`; `POST /conversations/[id]/read`
- `GET /images/[attachmentId]` → รูป inline ผ่าน `AttachmentAccess` (ไม่บันทึกการดาวน์โหลดทุกครั้งที่แสดง)
- `POST /images` → อัปโหลดรูปของแชต (JPEG/PNG/WebP ≤ 10 MB) ผ่าน `AttachmentService` เดิม (สแกนไวรัส ตรวจ signature)

ข้อความแชตไม่ถูกเขียนลง log, audit metadata, notification หรือ outbox

## ทดสอบ

- contract: schema ข้อความ (ว่าง, ยาวเกิน, มีรูปอย่างเดียว)
- core integration (MariaDB): ส่ง/อ่าน/ยังไม่อ่าน, ผู้ใช้ส่งเข้าบทสนทนาคนอื่นไม่ได้, ผู้ใช้ทั่วไปเรียก admin ไม่ได้, รูปต้องเป็นของผู้ส่ง, audit ไม่มีเนื้อความ, สิทธิ์เปิดรูป
- route unit tests: 401/403/400 และการส่งต่อไป service
- component tests: ปุ่มและตัวเลข, ส่งด้วย Enter, วางรูปจากคลิปบอร์ดแล้วแสดงตัวอย่าง, ผู้ดูแลระบบเปิดหลายหน้าต่าง (สูงสุด 3), Esc ไม่ปิดหน้าต่าง

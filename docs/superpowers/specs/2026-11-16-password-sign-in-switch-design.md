# สวิตช์การเข้าสู่ระบบด้วยชื่อผู้ใช้และรหัสผ่าน (design)

วันที่: 16 พ.ย. 2569 · ผู้ขอ: wasan · แบบที่เลือก: **B (อัตโนมัติ · เปิด · ปิด)** และ "ปิด feature ที่เกี่ยวข้อง"

## Intent

ทุกวันนี้การเข้าด้วยรหัสผ่านปิดเองเมื่อ ThaID หรือ Provider ID พร้อม และเปิดกลับได้ทางเดียวคือแก้ `PASSWORD_SIGN_IN=on` บนเซิร์ฟเวอร์ ผู้ดูแลระบบต้องการคุมเรื่องนี้จากหน้า ผู้ดูแลระบบ > การเข้าสู่ระบบ เอง และเมื่อรหัสผ่านปิดอยู่ ฟีเจอร์ที่ผูกกับรหัสผ่านต้องไม่โผล่ให้ใช้

## Goals

- โหมดสามทางบนการ์ด "ชื่อผู้ใช้และรหัสผ่าน" (การ์ดแรกของหน้า): **อัตโนมัติ** (ค่าเริ่มต้น = พฤติกรรมเดิมทุกอย่าง) · **เปิด** (เปิดตลอด) · **ปิด** (ปิดตลอด)
- แสดง "ตอนนี้เปิด/ปิดอยู่ เพราะ…" และเวลาที่เปลี่ยนล่าสุดแบบ `16 พ.ย. 2569 15:20` พร้อมชื่อผู้เปลี่ยน
- ทุกการเปลี่ยนยืนยันใน `ActionDialog` ที่บอก โหมดเดิม → โหมดใหม่ ปิดได้ด้วยปุ่มเท่านั้น
- เปลี่ยนโหมดกับ audit (`admin.sign_in_setting.update`, targetId `PASSWORD`, metadata `{ method, fromMode, toMode }`) อยู่ใน transaction เดียว
- เมื่อรหัสผ่าน **ปิดจริง** (ไม่ว่าเพราะโหมดใด) ฟีเจอร์เกี่ยวข้องถูกซ่อนในหน้าเว็บและถูกปฏิเสธที่ server (403 `password_sign_in_off`):
  - ปุ่ม/ลิงก์ "เปลี่ยนรหัสผ่าน" (โปรไฟล์ของฉัน, หน้าบุคคลของตนเอง) และหน้า `/change-password` (แสดงข้อความว่าปิดอยู่แทนฟอร์ม), `POST /api/auth/password`
  - ปุ่ม "รีเซ็ตรหัสผ่าน" บนหน้าบุคคล และ `POST /api/hr/people/[id]/password`
  - ข้อความ "ลืมรหัสผ่าน…" และฟอร์มบนหน้าเข้าสู่ระบบ / หน้า MCI (ทำงานแบบนี้อยู่แล้ว)

## Non-goals / anti-goals

- ไม่ทำเปิดชั่วคราวหรือเปิดเฉพาะกลุ่ม (แบบ C)
- ไม่ลบบัญชีหรือรหัสผ่านที่มีอยู่ ปิดแล้วเปิดกลับต้องใช้รหัสเดิมได้ทันที
- Anti-goal: ผู้ดูแลระบบล็อกตัวเองออกจากระบบด้วยหน้านี้

## Safety

- เลือก **ปิด** ได้เฉพาะเมื่อ ThaID หรือ Provider ID พร้อมใช้งาน มิฉะนั้นปฏิเสธด้วย `LAST_SIGN_IN_ROUTE` (ปุ่ม "ปิด" ยังกดได้ แต่ dialog แสดงข้อความ error)
- `PASSWORD_SIGN_IN=on` บนเซิร์ฟเวอร์ยังเป็นทางเข้าฉุกเฉินและชนะทุกโหมด หน้าเว็บบอกว่า "เปิดอยู่เพราะตั้งค่าบนเซิร์ฟเวอร์"
- อ่านค่าตั้งไม่ได้ (ฐานข้อมูลล่ม) = ปิด (fail closed) เหมือนเดิม
- ปิด ThaID/Provider ID ช่องทางสุดท้ายถูกปฏิเสธอยู่แล้ว (`LAST_SIGN_IN_ROUTE`)

## Approaches considered

- A การ์ดปุ่มเปิด/ปิด: ง่าย แต่เสียโหมดอัตโนมัติที่ใช้อยู่
- **B ปุ่มสามทาง (เลือก)**: เก็บพฤติกรรมเดิมเป็นค่าเริ่มต้น ใช้ `.mode-switch` แบบหน้าตั้งค่าโปรแกรม
- C เปิดชั่วคราว/เฉพาะกลุ่ม: ปลอดภัยสุด แต่ใหญ่กว่าเกือบสองเท่า

## How (builder calls, ของผมเอง)

- เก็บโหมดในตาราง `sign_in_setting` เดิม แถว `method = 'PASSWORD'`, `settings_json = {"mode":"AUTO|ON|OFF"}`, `enabled = 1` เฉพาะ ON — ไม่ต้องมี migration ใหม่; `routes().configured` นับเฉพาะแถว THAID/PROVIDER_ID
- `SignInSettingsService.routes()` คืน `passwordMode` ด้วย, `view()` คืน `password: { mode, updatedAt, updatedByName }`, เมธอดใหม่ `savePasswordMode(mode, actor)`
- `passwordSignInOpen({ externalRouteReady, override, mode })`: override on → เปิด; ON → เปิด; OFF → ปิด; AUTO → `!externalRouteReady`
- API ใหม่ `PUT /api/admin/sign-in-settings/password` `{ mode }` ผ่าน `withAdmin`; บันทึกแล้วล้าง cache
- การสร้างบัญชีผู้ใช้ (ชื่อผู้ใช้ + รหัสผ่านแรก) ในงานบุคคล **คงไว้** เพราะต้องมีบัญชีพร้อมเมื่อเปิดกลับหรือใช้ทางฉุกเฉิน

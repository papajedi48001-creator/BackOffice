# Module Navigation Design: one button per module, sub-menus inside the module

**Status:** draft for review
**Date:** 2026-10-21
**Source:** ผู้ใช้ขอ (2026-10-21) "ให้เมนูย่อยแต่ละเมนูที่แสดงในหน้าหลักไปอยู่ในโมดูลของตัวเอง" และ "หน้าหลักไม่ต้องมีเมนูย่อย นอกจากปุ่มลิงก์ไปแต่ละโมดูล" โดยกำหนดกลุ่มไว้ดังนี้:
- งานบุคคล มีเมนูบุคลากร หน่วยงาน และนำเข้าข้อมูลตั้งต้น
- สิทธิ์และการตรวจสอบ มีเมนูบทบาทและสิทธิ์ ผู้แทน และบันทึกการตรวจสอบ

**Assumption to confirm in review:** ใช้แบบ A ที่เสนอไว้ คือกดปุ่มโมดูลแล้วเปิดหน้าแรกที่ผู้ใช้มีสิทธิ์ทันที และเมนูย่อยเป็นแถบด้านบนของทุกหน้าในโมดูล (ไม่ใช่หน้าการ์ดคั่นอีกชั้นแบบ B) ผู้ใช้ยังไม่ได้เลือก A/B โดยตรง

## Purpose

หน้าหลักและเมนูด้านซ้ายแสดงเฉพาะ **โมดูล** (ตามความหมายใน `CONTEXT.md`) ส่วนหน้าย่อยของโมดูลแสดงเมื่อผู้ใช้เข้าไปในโมดูลนั้นแล้ว เพื่อให้หน้าหลักสั้น อ่านง่าย และโตได้เมื่อมีโมดูลเพิ่ม

## Current behaviour

- `moduleRegistry` ใน `apps/web/src/lib/modules.ts` มีรายการต่อ **หน้า** ไม่ใช่ต่อโมดูล: บุคลากร, หน่วยงาน, นำเข้าข้อมูลตั้งต้น, บทบาทและสิทธิ์, ผู้แทน, บันทึกการตรวจสอบ เป็นปุ่มแยกบนหน้าหลัก และเป็นเมนูแยกด้านซ้าย
- หน้าหลักแบ่งหัวข้อเป็นกลุ่ม (งานของฉัน, บุคลากรและองค์กร, งานบริการ, ความปลอดภัยและการตรวจสอบ, โมดูลที่กำลังพัฒนา)
- จองห้องประชุมเป็นรายการเดียวอยู่แล้ว แต่หน้าย่อย (การจองของฉัน, รออนุมัติ, จัดการห้อง) เป็นลิงก์มุมขวาบนของหน้าปฏิทินเท่านั้น หน้าอื่นในโมดูลไม่มีทางกลับไปหน้าย่อยอื่น

## Decisions

| เรื่อง | ทางเลือกที่ใช้ | เหตุผล |
|---|---|---|
| หน่วยของ registry | หนึ่ง `ModuleEntry` ต่อหนึ่งโมดูล มี `pages: ModulePage[]` (`{ href, labelKey, visible(subject) }`) เรียงตามลำดับแถบเมนูย่อย | หน้าหลัก เมนูซ้าย และแถบเมนูย่อยอ่านจากที่เดียว โมดูลใหม่ยังเพิ่มแค่รายการเดียว |
| โมดูลที่ live | `requests` คำขอ (`/requests`), `notifications` การแจ้งเตือน (`/notifications`), `hr` งานบุคคล (บุคลากร `/hr/people`, หน่วยงาน `/hr/organizations`, นำเข้าข้อมูลตั้งต้น `/hr/imports`), `room-booking` จองห้องประชุม (ปฏิทิน `/rooms`, การจองของฉัน `/rooms/bookings`, รออนุมัติ `/rooms/approvals`, จัดการห้อง `/rooms/manage`), `access` สิทธิ์และการตรวจสอบ (บทบาทและสิทธิ์ `/access/roles`, ผู้แทน `/access/delegations`, บันทึกการตรวจสอบ `/audit`) | ตามที่ผู้ใช้กำหนด; รหัส `hr` ตรงกับ `module_code` ของเจ้าของข้อมูล HR; `requests`, `notifications`, `room-booking` คงรหัสเดิมเพื่อให้ `moduleLabel()` ของการแจ้งเตือนเดิมยังถูก |
| สิทธิ์เห็นหน้าย่อย | บุคลากร/หน่วยงาน: `hr-reader` หรือ `hr-manager`; นำเข้าข้อมูลตั้งต้น: `canActHospitalWide(subject, 'hr.person.manage', 'hr')`; บทบาทและสิทธิ์/ผู้แทน: `hr-manager`; รออนุมัติ: มีขอบเขต `room.booking.decide`; จัดการห้อง: มีขอบเขต `room.manage`; ที่เหลือ: ทุกคนที่เข้าระบบ | ย้ายกฎเดิมจากรายการระดับหน้ามาไว้ที่ `pages[].visible` โดยไม่เปลี่ยนความหมาย; กฎห้องประชุมเหมือน `covers()` ที่หน้าปฏิทินใช้อยู่ |
| สิทธิ์เห็นโมดูล | โมดูลแสดงเมื่อมีหน้าย่อยที่มองเห็นอย่างน้อยหนึ่งหน้า | ผู้ใช้ไม่มีบทบาท HR ไม่เห็นปุ่มงานบุคคลเลย; ผู้ใช้ทั่วไปยังเห็น "สิทธิ์และการตรวจสอบ" เพราะเห็นบันทึกการตรวจสอบได้ (เหมือนเดิม) |
| ลิงก์ของปุ่มโมดูล | `href` ของหน้าย่อยแรกที่ผู้ใช้มองเห็น | ไปถึงหน้าที่ใช้งานในคลิกเดียว ไม่ต้องมีหน้า `/hr` หรือ `/access` ใหม่ |
| หน้าหลัก | ส่วนต้อนรับและตัวเลข "คำขอรอพิจารณา" / "การแจ้งเตือนที่ยังไม่อ่าน" คงเดิม; ตามด้วยตารางปุ่มโมดูล live ชุดเดียว **ไม่มีหัวข้อกลุ่ม**; แล้วหัวข้อ "โมดูลที่กำลังพัฒนา" กับปุ่มจางเหมือนเดิม | ผู้ใช้: "หน้าหลักไม่ต้องมีเมนูย่อย นอกจากปุ่มลิงก์ไปแต่ละโมดูล"; หัวข้อกลุ่มที่มีปุ่มเดียวไม่ช่วยอะไร; `group` คงไว้ใช้กำหนดสีไอคอนเท่านั้น |
| ตัวเลขบนปุ่มโมดูล | คงเดิม: คำขอ = รอพิจารณา, การแจ้งเตือน = ยังไม่อ่าน, จองห้องประชุม = `badge()` เดิม | ไม่เปลี่ยนพฤติกรรม |
| เมนูด้านซ้าย | หน้าหลัก + โมดูล live ที่มองเห็น หนึ่งรายการต่อโมดูล; รายการ active เมื่อ path ปัจจุบันอยู่ในหน้าย่อยใดของโมดูล (เช่น `/audit` ทำให้ "สิทธิ์และการตรวจสอบ" active) | เมนูซ้ายสอดคล้องกับหน้าหลัก |
| แถบเมนูย่อย | คอมโพเนนต์ `ModuleTabs` (`<nav aria-label="<ชื่อโมดูล>">` + ลิงก์, `aria-current="page"` ที่หน้าปัจจุบัน) แสดงเหนือเนื้อหาของทุกหน้าในโมดูลที่มีหน้าย่อยมองเห็นได้ **ตั้งแต่ 2 หน้า**; วางผ่าน `layout.tsx` ของ route (`hr`, `access`, `audit`, `rooms`) ที่เรียก `ModuleTabsFor({ code })` ฝั่งเซิร์ฟเวอร์ | หน้าเดิมไม่ต้องแก้เนื้อหา; โมดูลหน้าเดียว (คำขอ, การแจ้งเตือน) ไม่มีแถบ |
| หน้าปฏิทินห้องประชุม | ลบลิงก์ "รออนุมัติ", "จัดการห้อง", "การจองของฉัน" จากมุมขวาบน (ย้ายไปแถบเมนูย่อย) คงปุ่ม "จองห้อง" ไว้ | ไม่ซ้ำกับแถบ |
| ความปลอดภัย | การซ่อนเมนูไม่ใช่การกันสิทธิ์; ทุกหน้าและ API ยังตรวจสิทธิ์เองเหมือนเดิม ไม่แก้โค้ดตรวจสิทธิ์ของหน้าใด | ตาม CLAUDE.md |
| ข้อความ | เพิ่มใน `packages/i18n/src/th.ts`: `moduleHr` "งานบุคคล", `moduleHrDescription` "บุคลากร หน่วยงาน และนำเข้าข้อมูลตั้งต้น", `moduleAccess` "สิทธิ์และการตรวจสอบ", `moduleAccessDescription` "บทบาทและสิทธิ์ ผู้แทน และบันทึกการตรวจสอบ", `roomCalendarTab` "ปฏิทิน"; ป้ายแถบอื่นใช้คีย์เดิม (`people`, `organizations`, `hrImport`, `roles`, `delegations`, `audit`, `myRoomBookings`, `roomApprovals`, `roomManage`); ลบคีย์ที่ไม่ใช้แล้ว (`launcherGroup*` ยกเว้น planned, คำอธิบายรายหน้า) | ใช้ศัพท์ที่มีอยู่ |
| `CONTEXT.md` | เพิ่มศัพท์ **เมนูย่อยของโมดูล**: แถบลิงก์ไปหน้าย่อยภายในโมดูลเดียว แสดงเฉพาะหน้าที่ผู้ใช้มีสิทธิ์ (_Avoid_: tab, submenu) | ศัพท์ใหม่ต้องอยู่ใน CONTEXT.md ก่อนใช้ |
| เอกสารโมดูล | แก้ `docs/integration/modules.md` ข้อ 1 ให้เป็นรูปแบบ `pages` และวิธีวาง `layout.tsx` | โมดูลที่พัฒนาในเธรดอื่นใช้รูปแบบใหม่ |

## Interfaces

```ts
export interface ModulePage { href: string; labelKey: MessageKey; visible(subject: AccessSubject): boolean; }
export interface ModuleEntry {
  code: string; labelKey: MessageKey; descriptionKey: MessageKey; icon: ModuleIconName; group: ModuleGroup;
  status: 'live' | 'planned';
  pages: ModulePage[];            // planned: one page, never linked
  badge?(db: Database, subject: AccessSubject): Promise<number>;
}
export function visiblePages(entry: ModuleEntry, subject: AccessSubject): ModulePage[];
export function visibleModules(subject: AccessSubject): Array<ModuleEntry & { href: string }>; // planned + live with ≥1 visible page; href = first visible page
export function navigationFor(subject: AccessSubject): NavigationItem[]; // NavigationItem gains matchPrefixes: string[]
export function moduleLabel(code: string | null): string; // unchanged
```

## Testing

- `modules.test.ts`:
  - ผู้ใช้ไม่มีบทบาท: เห็น คำขอ, การแจ้งเตือน, จองห้องประชุม, สิทธิ์และการตรวจสอบ (ลิงก์ไป `/audit`) และไม่เห็นงานบุคคล
  - `hr-reader`: งานบุคคลลิงก์ไป `/hr/people`, หน้าย่อยคือบุคลากร + หน่วยงาน (ไม่มีนำเข้า)
  - `hr-manager` ขอบเขตหน่วยงานเดียว: ไม่เห็นนำเข้าข้อมูลตั้งต้น; `hr-manager` ทั้งโรงพยาบาล + เจ้าของข้อมูล `hr`: เห็นครบสามหน้า
  - `room-booking-approver`: จองห้องประชุมมีหน้ารออนุมัติ; ผู้ใช้ทั่วไปไม่มี
  - ไม่มีรายการระดับหน้าเดิม (`hr-people`, `access-roles` ฯลฯ) เหลือใน registry
  - `moduleLabel` เดิมยังผ่าน
- `module-launcher.test.tsx`: ไม่มีหัวข้อกลุ่มของโมดูล live, ไม่มีลิงก์ไปหน้าย่อยที่ไม่ใช่หน้าแรก (เช่น `/hr/organizations`), ปุ่ม planned ยังไม่เป็นลิงก์
- `sidebar-nav.test.tsx`: `/audit` ทำให้ "สิทธิ์และการตรวจสอบ" มี `aria-current="page"`
- `module-tabs.test.tsx`: แสดงเฉพาะหน้าที่ส่งมา, `aria-current` ที่หน้าปัจจุบัน, ไม่ render เมื่อมีหน้าเดียว
- หน้าปฏิทินห้องประชุมไม่มีลิงก์ `/rooms/approvals` ในหัวหน้า
- ตรวจด้วยเบราว์เซอร์จริงบนเครื่อง: เข้า `hr.demo` แล้วดูหน้าหลัก, กดงานบุคคล, สลับแถบ, เข้า `/audit` และดูเมนูซ้าย active

## Out of scope

- หน้าใหม่ของโมดูล (`/hr`, `/access`) และหน้า "รอฉันพิจารณา" ของคำขอ
- เปลี่ยน URL ของหน้าเดิม (เช่น ย้าย `/audit` ไปใต้ `/access`)
- เปลี่ยนการตรวจสิทธิ์ของหน้าและ API

# Smart Money Waritchaphum ใน BackOffice — design

วันที่: 2026-11-13 · โมดูล `smart-money` (`/money`) · บันทึกการตัดสินใจ: `/mnt/project-files/smart-money/decisions.md`
ต้นแบบ: repo `ongrx25/Smart_Money_Waritchaphum` (PHP) — spec ต้นฉบับของแต่ละหน้าอยู่ใน `docs/superpowers/specs/` ของ repo นั้น ศัพท์อยู่ใน `CONTEXT.md` ของ repo นั้น

## 1. เจตนาและเหตุผล

Smart Money เป็นระบบติดตามการเงินและการเรียกเก็บค่ารักษาของโรงพยาบาล เขียนด้วย PHP แยกจาก BackOffice ใช้รหัสผู้ดูแลใน `.env` แทนการล็อกอิน และทุกเครื่องใน LAN เปิดดูได้ ทั้งที่หลายหน้ามี HN ชื่อผู้ป่วย และเลขบัตรประชาชน

ผู้ใช้ต้องการย้าย **ทั้งระบบ** เข้ามาเป็นโมดูลหนึ่งของ BackOffice แล้ว **เลิกใช้ระบบ PHP เดิม** และให้เปิดดูได้ **เฉพาะเจ้าหน้าที่ที่ได้รับอนุญาต** ผ่านล็อกอินและสิทธิ์ของ BackOffice

ผู้ใช้ย้ำ (2026-11-13): ไม่ต้องใช้ PHP เขียนด้วยภาษาเดียวกับโมดูลอื่นได้ แต่ **การทำงานและการแสดงผลข้อมูลต้องเทียบเท่าระบบเดิม** และ **ต้องสวยเหมือนระบบเดิม** (ดู 7.5)

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / สิ่งที่ถือว่าล้มเหลว

**เป้าหมาย**
- ย้าย 4 หน้าให้ครบความสามารถเดิม: ลูกหนี้ทันตกรรม, เงินโอน สปสช., monitor กองทุนย่อย FDH, Point ฟื้นฟูผู้พิการ ตัวเลขทุกตัวต้องตรงกับระบบเดิมเมื่อใช้ข้อมูลชุดเดียวกัน
- คนที่ไม่ได้รับอนุญาตไม่เห็นโมดูล และเข้า URL หรือ API ตรง ๆ ไม่ได้ (ตรวจที่เซิร์ฟเวอร์)
- ใช้ส่วนประกอบหน้าจอเดิมของ BackOffice (`ModuleLayout`, แถบย่อย, `FormDialog`, `ActionDialog`, `ThaiDateInput`, ตาราง) ตาม `DESIGN.md`

**ไม่ใช่เป้าหมาย**
- เพิ่มความสามารถใหม่ที่ระบบเดิมไม่มี (นอกจากที่ระบุในแต่ละรอบ)
- เขียนข้อมูลลง HOSxP — อ่านอย่างเดียวเสมอ
- ย้ายไฟล์ JSON ของระบบเดิม — ข้อมูลเก่าเข้าโดยอัปโหลดไฟล์ต้นฉบับชุดเดิมซ้ำ

**ถือว่าล้มเหลวแม้ทำงานได้**
- ตัวเลขบน dashboard ไม่ตรงกับระบบเดิม (ผู้ใช้จะเลิกเชื่อ)
- เลขบัตรประชาชนเต็มโผล่ใน UI, URL, log, audit หรือ outbox
- หน้าตาต่างจากโมดูลอื่นจนดูเป็นอีกระบบ

## 3. ข้อจำกัด

- กติกาใน `CLAUDE.md`: สิทธิ์ตรวจที่เซิร์ฟเวอร์ทุก action, สิทธิ์ใหม่ map ใน `permissionModules`, migration แบบเพิ่มอย่างเดียวและลงทะเบียนใน `migrate.ts`, เก็บ UTC แสดงเวลาไทย, ช่องวันที่ใช้ `ThaiDateInput` แสดง `13 พ.ย. 2569`, popup ปิดได้จากปุ่มเท่านั้น, audit/outbox เขียนในธุรกรรมเดียวกับการเปลี่ยนข้อมูล
- HOSxP: ใช้การเชื่อมต่อเดิมที่ตั้งไว้ใน "ตั้งค่าการเชื่อมต่อ" (`HosxpSettingsService.resolve()`) ไม่สร้างการตั้งค่าใหม่ ฐาน HOSxP เป็น TIS-620 ต้องแปลงข้อความเป็น UTF-8 ให้ถูก
- ไม่มีไลบรารีกราฟใน BackOffice ปัจจุบัน

## 4. วิธีสร้าง (Approaches)

1. **เขียนใหม่ใน BackOffice ทั้งหมด** — ตัวอ่านไฟล์และการคำนวณเป็น TypeScript ใน `packages/core`, ข้อมูลที่อัปโหลดเก็บในตาราง MariaDB, หน้าจอเป็น Next.js ใช้ส่วนประกอบเดิม งานมากที่สุด แต่ได้ระบบเดียว มี audit และสิทธิ์ครบ **← ผู้ใช้เลือก ("จัดไป" 2026-11-13)**
2. เขียนหน้าจอใหม่แต่เก็บข้อมูลเป็นไฟล์ JSON แบบเดิม — เร็วกว่า แต่สำรองข้อมูลและตรวจสิทธิ์ยาก และต่างจากโมดูลอื่น
3. ให้ BackOffice เปิดระบบ PHP เดิมข้างใน — ตัดออก เพราะหน้าตาไม่เหมือนโมดูลอื่นและยังต้องดูแลระบบเดิม ขัดกับการเลิกใช้ระบบเดิม

## 5. สิทธิ์ (ทั้งโมดูล — ตัดสินแล้ว "เอาแบบ lab")

- **ผู้ดูแล Smart Money** = ผู้ดูแลระบบ หรือ ผู้จัดการโมดูล Smart Money (บทบาทใหม่ `money-manager` ถือสิทธิ์ใหม่ `money.manage` ซึ่ง map กับโมดูล `smart-money` ใน `permissionModules` และ `moduleManagerRoles`) ทำได้ทุกอย่าง: เห็นทุกหน้า อัปโหลด/ลบไฟล์ และเพิ่ม/ถอด/แก้สมาชิก
- **เจ้าหน้าที่ที่ได้รับอนุญาต** = มีชื่อในตาราง `money_member` (เพิ่มในหน้าตั้งค่าของโมดูล) พร้อมรายการ **หน้าที่เห็นได้** (`money_member_page`: `dental`, `nhso`, `fdh`, `disability`) ดูได้อย่างเดียวเฉพาะหน้าที่ติ๊กไว้
  - การอ่านของ Claude: "แบบ lab" = เหมือน Lab ที่ผูกเจ้าหน้าที่กับงาน จึงให้ติ๊กหน้ารายคน (ผู้ใช้แก้ได้)
- คนที่ไม่ใช่ทั้งสองแบบ: ไม่เห็นปุ่มโมดูลบนหน้าหลัก ไม่เห็นเมนู เข้า URL ได้หน้า "ไม่มีสิทธิ์" API ตอบ 403
- รูปแบบโค้ดตาม `lab-access.ts`: `canManageMoney(subject)`, `loadMoneyMember(db, personId)`, `moneyCan(member, manages, page)` ใช้ทั้งในหน้า, API และ `available` ของเมนูใน `modules.ts`
- ทุกการเพิ่ม/แก้/ถอดสมาชิก การอัปโหลด และการลบชุดข้อมูล ลง audit (ไม่ใส่ข้อมูลผู้ป่วยใน metadata)

## 7. รอบ 1 — รายละเอียด

### 7.1 โครงโมดูล
- ลงทะเบียน `smart-money` ใน `apps/web/src/lib/modules.ts` (ชื่อ "Smart Money", คำอธิบาย "ติดตามการเงินและการเรียกเก็บค่ารักษาพยาบาล", กลุ่ม `services`, ไอคอนใหม่แนวเหรียญ/กระเป๋าเงินใน `module-icon.tsx`) `available` = ผู้ดูแล หรือสมาชิกที่มีอย่างน้อย 1 หน้า
- แถบย่อย: ภาพรวม (`/money`) · ลูกหนี้ทันตกรรม (`/money/dental`) · ตั้งค่า (`/money/settings`, ผู้ดูแลเท่านั้น) — หน้ารอบถัดไปเพิ่มเป็นรายการในแถบย่อยเมื่อสร้าง
- หน้า `/money` = ปุ่มไปแต่ละหน้าที่คนนั้นเห็นได้ (เหมือนหน้าเมนูของระบบเดิม) พร้อมคำอธิบายหน้า
- ไม่มี `submitAction` (ไม่ใช่โมดูลยื่นคำขอ)
- โหมดโมดูล (เปิด/พัฒนา/ปิด) ใช้กลไกเดิมของหน้าตั้งค่าโปรแกรม

### 7.2 หน้าตั้งค่าสมาชิก (`/money/settings`)
- ตารางสมาชิก: ชื่อ ตำแหน่ง หน้าที่เห็นได้ (ชิป) ปุ่มแก้ไข / ถอด
- "เพิ่มเจ้าหน้าที่" และ "แก้ไข" เปิด `FormDialog`: เลือกบุคลากร (ค้นหาจากทะเบียน HR แบบเดียวกับหน้าสมาชิก Lab) + ช่องติ๊กหน้า (รอบ 1 มีแค่ "ลูกหนี้ทันตกรรม" ช่องของหน้าในอนาคตเพิ่มตามรอบ) ต้องติ๊กอย่างน้อย 1 หน้า
- "ถอด" ยืนยันใน `ActionDialog`
- ตาราง `money_member (person_id PK, created_at, created_by)` และ `money_member_page (person_id, page, PK คู่)`

### 7.3 หน้าลูกหนี้ทันตกรรม (`/money/dental`) — พฤติกรรมเดียวกับ `modules/dental_claims` ของระบบเดิม
**ข้อมูล:** query เดียวกับ `DentalClaimsRepository::fetch` ของระบบเดิม (ovstdiag × ovst × patient × icd101 × pttype × paccountopd × paccount × vn_stat) รหัสโรค K00–K119 เฉพาะ visit ที่ `rcpt_money > 0` หรือ `paid_money < ผลรวม inc01–inc16` อ่านสดจาก HOSxP ทุกครั้งที่เปิดหน้า ไม่เก็บสำเนาใน MariaDB ค่าวันที่ส่งเป็น parameter เท่านั้น
- query ระบบเดิมปิด `ONLY_FULL_GROUP_BY` ในเซสชัน ให้ทำเหมือนกันหรือเขียนใหม่ให้ได้ผลเดียวกัน (เลือกเองได้ แต่ผลต้องตรง)
- ข้อความภาษาไทยจาก HOSxP (TIS-620) ต้องแสดงถูก
- **ผังบัญชีเมื่อมีหลายแถว (การตัดสินใจของ Claude):** query เดิม join `paccountopd` ทั้ง "ปีเดียวกับวันรับบริการ" และ "ปีล่าสุด" แล้วปล่อยให้ MariaDB สุ่มเลือกหนึ่งแถว ระบบใหม่ใช้กฎตายตัว: แถวปีเดียวกับวันรับบริการก่อน ไม่มีจึงใช้ปีล่าสุด ถ้ายังมีหลายแถวเลือก `paccount` น้อยสุด ยอดเงินไม่กระทบ ต่างจากระบบเดิมได้เฉพาะชื่อผังบัญชีในกรณีที่ระบบเดิมสุ่ม
- **จำกัดช่วงไม่เกิน 366 วัน** เหมือนระบบเดิม เพื่อไม่ให้ query หนักฐาน HOSxP — **การตัดสินใจของ Claude:** แสดงข้อความที่ตัวกรองแทนการตัดช่วงเงียบ ๆ แบบเดิม

**ตัวกรอง (ฟอร์มตัวกรองบนหน้า ไม่ใช่ popup):** ตั้งแต่วันที่ / ถึงวันที่ (`ThaiDateInput`, ค่าเริ่มต้น = เดือนปัจจุบันตามเวลาไทย) ปุ่มลัด เดือนนี้ · เดือนที่แล้ว · ปีงบประมาณนี้ (1 ต.ค.–30 ก.ย.) สลับ "แยกตาม" สิทธิการรักษา / ผังบัญชี และ "ช่วงเวลา" รายวัน / รายเดือน ค่าตัวกรองอยู่ใน query string (วันที่และตัวเลือกเท่านั้น ไม่มีข้อมูลผู้ป่วย)

**การ์ดสรุป 4 ใบ:** ผู้รับบริการ (คน + visit) · ค่ารักษารวม · ชำระแล้ว · มูลค่าลูกหนี้/เรียกเก็บ — ยอดเงินนับต่อ visit ครั้งเดียว (1 visit หลายรหัสโรค = หลายแถวแต่เงินนับครั้งเดียว) ตาม `summarize` ของระบบเดิม

**กราฟ:**
- ค่ารักษารวมแยกตามกลุ่มที่เลือก แสดงจำนวนคนต่อกลุ่ม และลูกหนี้ใน tooltip/ป้าย เรียงจากมากไปน้อย กลุ่มเกิน 8 กลุ่มแสดงเป็นแท่งแนวนอน
- แนวโน้มตามช่วงเวลา (รายวัน/รายเดือน) ของค่ารักษารวมและลูกหนี้ — ระบบเดิมคำนวณ `by_period` และมีปุ่มสลับแต่ไม่ได้วาดกราฟนี้ **(การตัดสินใจของ Claude: วาดกราฟนี้ด้วย เพื่อให้ปุ่มรายวัน/รายเดือนมีผลกับหน้าจอ)**
- **การตัดสินใจของ Claude:** ไม่เพิ่มไลบรารีกราฟ ทำส่วนประกอบกราฟแท่งด้วย SVG/CSS เองใน `apps/web/src/components/` ใช้สีจาก token ใน `DESIGN.md` ทุกแท่งมีตัวเลขเป็นข้อความ (ไม่สื่อด้วยสีอย่างเดียว) และนำไปใช้ซ้ำในรอบ 2–4

**ตาราง:**
- สรุปตามกลุ่ม: กลุ่ม (รหัส + ชื่อ) · คน · visit · ค่ารักษารวม · ลูกหนี้ + แถวรวม
- รหัสโรคที่พบบ่อย Top 10: ICD-10 · ชื่อโรค · จำนวน (นับทุกแถว)
- รายละเอียดรายการ: วันที่ · HN · ชื่อ-สกุล · ICD-10 · ชื่อโรค · สิทธิ · ผังบัญชี · ค่ารักษารวม · ชำระแล้ว · ลูกหนี้ มีช่องค้นหาในหน้า (HN / ชื่อ / รหัสโรค / สิทธิ / ผังบัญชี กรองฝั่งเบราว์เซอร์ ไม่ส่งคำค้นไปเซิร์ฟเวอร์) และหมายเหตุเรื่องนับเงินต่อ visit
- ตัวเลขเงินชิดขวา ทศนิยม 2 ตำแหน่ง วันที่แสดงแบบไทย

**ส่งออก:** ปุ่ม "ดาวน์โหลด CSV" ไฟล์ UTF-8 มี BOM คอลัมน์เดียวกับระบบเดิม (VN, วันที่รับบริการ, HN, ชื่อ-สกุล, ICD-10, ชื่อโรค, รหัสสิทธิ, ชื่อสิทธิ, ผังบัญชี, ค่ารักษารวม, ชำระแล้ว, ยอดเรียกเก็บ)
- **การตัดสินใจของ Claude:** ใครเห็นหน้านี้ได้ก็ดาวน์โหลดได้ (ระบบเดิมให้ทุกคนดาวน์โหลด และการบังคับสิทธิ์ `data.export` จะทำให้เจ้าหน้าที่การเงินที่ได้รับอนุญาตดาวน์โหลดไม่ได้) ทุกการดาวน์โหลดลง audit พร้อมช่วงวันที่และจำนวนแถว ไม่ใส่ข้อมูลผู้ป่วย

**สถานะผิดพลาด:**
- ยังไม่ได้ตั้งการเชื่อมต่อ HOSxP → ข้อความ "ยังไม่ได้ตั้งค่าการเชื่อมต่อ HOSxP" (ผู้ดูแลระบบเห็นลิงก์ไปหน้าตั้งค่าการเชื่อมต่อ)
- เชื่อมต่อ/query ไม่สำเร็จ → ข้อความทั่วไป ไม่แสดงรายละเอียดการเชื่อมต่อหรือรหัสผ่าน log เฉพาะรหัสข้อผิดพลาด
- ไม่มีข้อมูลในช่วง → "ไม่พบข้อมูลในช่วงวันที่ที่เลือก"
- ช่วงวันที่ผิด (สิ้นสุดก่อนเริ่ม) → ข้อความที่ตัวกรอง ไม่ query

### 7.5 หน้าตา ("สวยเหมือนระบบเดิม")
การอ่านของ Claude (ขอผู้ใช้ยืนยัน): โครงหน้า เมนู แถบบน ฟอนต์ ปุ่ม popup และช่องวันที่เป็นของ BackOffice (`ModuleLayout`) ส่วน **เนื้อหา dashboard** ยกความสวยของระบบเดิมมา: การ์ดสรุปตัวเลขใหญ่ 4 ใบเรียงแถว (ใบลูกหนี้เน้นสี) ปุ่มลัดช่วงวันที่แบบชิป ปุ่มสลับแบบ segmented กราฟแท่งมุมมนพร้อมตัวเลขบนแท่ง ตารางสองคอลัมน์ข้างกัน และตารางรายละเอียดเลื่อนในกรอบ ใช้สีจาก token ของ BackOffice (น้ำเงินโรงพยาบาล) แทนสีเขียวของระบบเดิม เพื่อไม่ให้ดูเป็นอีกระบบ จอแคบ (390px) การ์ดเรียง 2×2 ตารางเลื่อนแนวนอนในกรอบ
- เป็นข้อยกเว้นของกติกา "ไม่ใช้ card จำนวนมาก" ใน `DESIGN.md` สำหรับหน้า dashboard ของ Smart Money — เพิ่มย่อหน้าใน `DESIGN.md`
- ส่งภาพหน้าจอ 1280 และ 390 ให้ผู้ใช้ดูก่อน merge

### 7.4 เทสต์ที่ต้องมี
- unit: `summarize` (นับเงินต่อ visit, จัดกลุ่มสิทธิ/ผังบัญชี, `(ไม่ระบุผังบัญชี)`, รายวัน/รายเดือน, Top 10) ด้วยชุดข้อมูลตัวอย่าง (fixture) ที่ได้ค่าคาดหวังจากการรัน `DentalClaimsRepository::summarize` ของ PHP เดิมกับ fixture เดียวกัน (มี PHP ในเครื่องพัฒนา)
- ตรวจเทียบกับข้อมูลจริง: หลังติดตั้ง ผู้ใช้เปิดหน้าเดิมกับหน้าใหม่ช่วงวันที่เดียวกัน เทียบการ์ดสรุปและตารางสรุป ก่อนปิดหน้าเดิม (ขอผู้ใช้ยืนยัน)
- unit: `moneyCan` / `canManageMoney` ทุกกรณี, `permissionModules` มี `money.manage`
- unit: ตัวช่วยช่วงวันที่ (ค่าเริ่มต้นเดือนนี้, เดือนที่แล้ว, ปีงบ) ตามเวลาไทย
- unit: CSV (BOM, หัวคอลัมน์, การ escape)
- integration (MariaDB): บริการสมาชิก (เพิ่ม/แก้/ถอด + audit ในธุรกรรมเดียวกัน, ต้องมี ≥1 หน้า, คนที่ไม่ใช่ผู้ดูแลทำไม่ได้)
- web: หน้า/API ปฏิเสธคนไม่มีสิทธิ์, เมนูซ่อน, ฟอร์มสมาชิกใน `FormDialog`, `date-fields.test.ts` ผ่าน
- HOSxP query: เทสต์ด้วยตัวอ่านปลอม (inject reader) — ไม่ต่อ HOSxP จริงใน CI

## 8. สิ่งที่ปล่อยให้ผู้สร้างตัดสินใจ
- ชื่อไฟล์/คลาสภายใน, การแบ่ง component, รูปไอคอน
- จะคำนวณสรุปบนเซิร์ฟเวอร์ (แนะนำ) หรือเบราว์เซอร์ — ตัวเลขต้องตรงระบบเดิม
- วิธีแปลง TIS-620 (ตั้ง charset ของการเชื่อมต่อ หรือแปลงหลังอ่าน) — ต้องแสดงไทยถูก
- สีของแต่ละแท่งกราฟ ภายใน token ที่มี

# ระบบรายงานวัสดุคงคลัง Lab — design

Request (wasan, 2026-11-10): ทำโมดูล "ระบบรายงานวัสดุคงคลัง Lab" ใน BackOffice แทนระบบเดิมที่เป็น Google Apps Script (ไม่เอาแบบเดิม) ใช้ login ของ BackOffice ระหว่างรอ SSO Provider ID. Superpowers brainstorming invoked through the Skill tool; requirements were grilled one question at a time (14 decisions + 3.1, log: `/mnt/project-files/lab-inventory/decisions.md`). ระบบเดิมอยู่ในโปรเจกต์อื่นที่เธรดนี้เปิดไม่ได้ คอลัมน์ของแม่แบบนำเข้าจะปรับให้ตรงกับ Sheet เดิมเมื่อผู้ใช้ส่งไฟล์มา (ไม่กระทบโครงสร้างข้อมูล).

โมดูลนี้ **แยกจากโมดูลคลังพัสดุ (`inventory`) ทั้งหมด**: ไม่ใช้ตาราง บริการ หรือสิทธิ์ของคลังพัสดุ (ข้อ 1).

## เป้าหมายและเกณฑ์สำเร็จ

- ยอดคงเหลือของคลังหลัก Lab และคลังย่อยของแต่ละงานถูกต้องตามรายการเคลื่อนไหวทุกวัน รายล็อตพร้อมวันหมดอายุ
- เจ้าหน้าที่ Lab ตัดใช้ได้ในไม่กี่วินาที (เลือกวัสดุ + จำนวน ระบบเลือกล็อตให้)
- ทุกการโอนเข้าคลังย่อยมีใบขอเบิกที่หัวหน้า Lab อนุมัติ
- (รอบ 2) สิ้นเดือนออกรายงาน ยกมา | รับ/โอนเข้า | ใช้/โอนออก | ปรับยอด | คงเหลือ ทั้งจำนวนและมูลค่า ปิดงวดแล้วตัวเลขไม่เปลี่ยน

## รอบการส่งมอบ (ข้อ 14)

- **รอบ 1 (spec นี้ลงรายละเอียดถึงระดับ implement):** ตั้งค่า (วัสดุ, คลังย่อย/งาน, ผู้ขาย, ประเภทการใช้, สมาชิกและบทบาท) + นำเข้ายอดยกมาและรับรอง + รับเข้า + ใบขอเบิก/อนุมัติ/จ่าย + ตัดใช้ + หน้ายอดคงเหลือและบัญชีวัสดุ
- **รอบ 2 (กำหนดพฤติกรรมไว้ที่นี่ จะเขียน plan แยก):** คำขอปรับยอดและใบนับสต็อก + รายงานประจำเดือน/ปิดงวด/ส่งออก Excel + เตือนใกล้หมด/ใกล้หมดอายุ + LINE สรุปเช้า

ข้อมูลรอบ 1 ออกแบบให้รอบ 2 ต่อได้โดยไม่ต้องย้ายข้อมูล (บัญชีเคลื่อนไหวเก็บชนิดรายการ วันที่รายการ และต้นทุนตั้งแต่วันแรก).

## ข้อมูล (migration `00NN_lab_inventory.sql` ถัดจากเลขล่าสุดบน main ตอน implement, additive; Drizzle `packages/db/src/schema/lab-inventory.ts`)

จำนวนทั้งหมดเป็น **จำนวนเต็มของหน่วยใช้** (`INT`), ราคาเป็น `DECIMAL(12,2)` บาทต่อหน่วยรับ, ต้นทุนต่อหน่วยใช้ `DECIMAL(14,4)` = ราคาต่อหน่วยรับ ÷ อัตราแปลง (คำนวณครั้งเดียวตอนสร้างล็อต). วันที่รายการเป็น `DATE` (วันตามเวลาไทย) เวลาบันทึกเป็น `DATETIME` UTC.

ตั้งค่า:
- `lab_section` (id, code, name, sort_order, is_active) — งาน = คลังย่อย seed: เคมีคลินิก, โลหิตวิทยา, จุลชีววิทยา, ธนาคารเลือด, ภูมิคุ้มกันวิทยา, จุลทรรศนศาสตร์คลินิก (แก้/ปิดใช้ได้)
- `lab_store` (id, kind `MAIN|SECTION`, section_id null สำหรับ MAIN) — seed คลังหลัก 1 แถว; สร้างอัตโนมัติเมื่อเพิ่มงาน; unique section_id
- `lab_item` (id, code unique, name, receive_unit, use_unit, units_per_receive ≥ 1, expiry_warn_days default 90, is_active) — `expiry_warn_days` ใช้รอบ 2
- `lab_item_reorder` (item_id, store_id, reorder_point) — ใช้รอบ 2 (สร้างตารางรอบ 1 เพื่อให้แก้ในหน้าวัสดุได้เลย)
- `lab_vendor` (id, name unique, phone, is_active)
- `lab_usage_type` (id, name unique, sort_order, is_active) seed 5 ค่า
- `lab_member` (person_id PK, role `HEAD|KEEPER|STAFF`, created_at, created_by)
- `lab_member_section` (person_id, section_id) PK คู่ — เฉพาะ STAFF
- `lab_setting` (key PK, value) เช่น `opening_certified_at`

สต็อก:
- `lab_lot` (id, item_id, lot_no, expiry_date null ได้ (ของไม่มีวันหมดอายุ), unit_cost, source `OPENING|RECEIPT`, receipt_line_id null, created_at) unique (item_id, lot_no, expiry_date, unit_cost) — รับล็อตเดิมซ้ำราคาเดิมรวมล็อตเดียว
- `lab_lot_balance` (lot_id, store_id, quantity ≥ 0) PK คู่ — ยอดปัจจุบัน แก้ใน transaction พร้อมบัญชีเคลื่อนไหวเสมอ (`SELECT … FOR UPDATE`)
- `lab_movement` (id, lot_id, store_id, quantity ± , kind `OPENING|RECEIPT|RECEIPT_VOID|ISSUE_OUT|ISSUE_IN|USE|USE_REVERSAL|ADJUSTMENT`, entry_date, usage_type_id null, ref_type, ref_id, note, created_by, created_at) — เพิ่มอย่างเดียว ไม่มี UPDATE/DELETE
- `lab_opening_line` (id, store_id, item_id, lot_no, expiry_date, quantity, unit_cost, row_no) + สถานะใน `lab_setting` (`DRAFT|SUBMITTED|CERTIFIED`)
- `lab_receipt` (id, doc_no `LR-2569-0001` รันต่อปีงบ พ.ศ., received_on, vendor_id, invoice_no, status `POSTED|VOIDED`, void_reason, created_by, created_at, voided_by, voided_at)
- `lab_receipt_line` (id, receipt_id, item_id, lot_no, expiry_date, quantity_receive, price_per_receive, lot_id)
- `lab_requisition` (id, doc_no `LQ-2569-0001`, section_id, status `SUBMITTED|RETURNED|REJECTED|APPROVED|ISSUED|CANCELLED`, requested_by, requested_at, decided_by, decided_at, decision_reason, issued_by, issued_at, issue_note)
- `lab_requisition_line` (id, requisition_id, item_id, quantity_requested, quantity_issued null)
- `lab_usage` (id, store_id, item_id, quantity, usage_type_id, entry_date, note, status `POSTED|REVERSED`, reverse_reason, created_by, created_at, reversed_by, reversed_at) — หนึ่งการตัดใช้แตกเป็นหลายแถวใน `lab_movement` ได้ถ้าใช้หลายล็อต

ทุกการเปลี่ยน (ตั้งค่า, สมาชิก, ยอดยกมา, รับเข้า/ยกเลิก, ใบขอเบิกทุกสถานะ, จ่าย, ตัดใช้/ยกเลิก) เขียน audit event และ outbox (ถ้ามี) ใน transaction เดียวกัน. audit metadata เก็บ id, เลขเอกสาร, รหัสวัสดุ, จำนวน ไม่เก็บเหตุผลการตัดสิน (ตามกฎโปรเจกต์: เหตุผลอยู่ในตารางเท่านั้น).

## พฤติกรรมรอบ 1

### 1. หน้าโมดูล `/lab`
แท็บตามสิทธิ์: **ภาพรวม**, **ตัดใช้**, **ใบขอเบิก**, **รับเข้า**, **ยอดคงเหลือ**, **ตั้งค่า**. ภาพรวมแสดง: ใบขอเบิกรออนุมัติ (หัวหน้า) / รอจ่าย (ผู้ดูแลคลัง) / ของงานฉัน (เจ้าหน้าที่) และปุ่มใหญ่ "ตัดใช้". ก่อนยอดยกมาถูกรับรอง หน้าภาพรวมแสดงแถบ "ยังไม่เริ่มใช้งาน: รอรับรองยอดยกมา" และปุ่มรับเข้า/ขอเบิก/ตัดใช้ปิดอยู่ (server คืน 409 `OPENING_NOT_CERTIFIED`).

### 2. ตั้งค่า
แท็บ วัสดุ, งาน/คลังย่อย, ผู้ขาย, ประเภทการใช้, สมาชิก. เพิ่ม/แก้ใน `FormDialog`, ปิดใช้ใน `ActionDialog` (ปิดใช้แทนลบ). อัตราแปลงของวัสดุแก้ไม่ได้เมื่อมีล็อตแล้ว (409 `ITEM_HAS_STOCK`) เพราะต้นทุนต่อหน่วยใช้คำนวณจากค่านี้. หน้าวัสดุแก้จุดสั่งซื้อต่อคลังได้ (ใช้แจ้งเตือนรอบ 2).

### 3. ยอดยกมา (ข้อ 9)
- ดาวน์โหลดแม่แบบ **CSV แบบ UTF-8 มี BOM** (เปิดและบันทึกใน Excel ได้ตรงภาษาไทย ตามกลไก CSV เดิมของ HR/ลา) สองไฟล์: ทะเบียนวัสดุ (รหัส, ชื่อ, หน่วยรับ, หน่วยใช้, อัตราแปลง, จุดสั่งซื้อคลังหลัก) และยอดยกมา (คลัง = "คลังหลัก" หรือรหัสงาน, รหัสวัสดุ, เลขล็อต, วันหมดอายุ `YYYY-MM-DD` หรือ พ.ศ. `DD/MM/YYYY`, จำนวนหน่วยใช้, ต้นทุนต่อหน่วยใช้)
- อัปโหลดแล้วตรวจทั้งไฟล์ก่อนบันทึก รายงานข้อผิดพลาดรายแถว (ไม่บันทึกบางส่วน) ทะเบียนวัสดุนำเข้าแบบเพิ่ม/อัปเดตตามรหัส; ยอดยกมาแทนที่ร่างเดิมทั้งชุด
- ผู้ดูแลคลังแก้รายแถวบนหน้าจอได้ → "ส่งรับรอง" (`ActionDialog`) → หัวหน้า Lab ดูยอดรวมต่อคลัง (จำนวนรายการ, มูลค่า) แล้ว "รับรอง" หรือ "ตีกลับ" พร้อมเหตุผล → รับรองแล้วสร้าง `lab_lot` + `lab_lot_balance` + `lab_movement OPENING` (entry_date = วันที่รับรอง) ใน transaction เดียว และเปิดใช้งานโมดูล รับรองแล้วแก้ยอดยกมาไม่ได้อีก (แก้ผ่านปรับยอดรอบ 2)

### 4. รับเข้า (ข้อ 12, คลังหลักเท่านั้น)
- ฟอร์ม `FormDialog`: วันที่รับ (ค่าเริ่มต้นวันนี้, ไม่เกินวันนี้), ผู้ขาย, เลขที่ใบส่งของ/ใบกำกับ, บรรทัด: วัสดุ, เลขล็อต, วันหมดอายุ (ไม่บังคับ ต้องหลังวันรับ), จำนวนหน่วยรับ, ราคาต่อหน่วยรับ. แสดงจำนวนหน่วยใช้และมูลค่ารวมให้ทันที
- บันทึก: เลขเอกสารถัดไป, สร้าง/รวมล็อต, `RECEIPT` เข้าคลังหลัก = จำนวนหน่วยรับ × อัตราแปลง
- ยกเลิกใบรับ (`ActionDialog` + เหตุผล): ได้เฉพาะเมื่อทุกล็อตจากใบนี้ยังไม่มีรายการอื่นนอกจาก `RECEIPT` และ (รอบ 2) เดือนยังไม่ปิดงวด → `RECEIPT_VOID` ลบยอดคืน; ไม่ผ่าน → 409 `RECEIPT_LOT_IN_USE`

### 5. ใบขอเบิก (ข้อ 10)
- สร้าง (`FormDialog`): งาน (เจ้าหน้าที่เห็นเฉพาะงานตัวเอง), บรรทัด วัสดุ + จำนวนหน่วยใช้ (แสดงยอดคลังหลักและคลังย่อยปัจจุบันเป็นข้อมูลประกอบ) → `SUBMITTED` แจ้งหัวหน้า Lab (กระดิ่ง)
- หัวหน้า Lab: **อนุมัติ** / **ตีกลับ** (ผู้ขอแก้แล้วส่งใหม่) / **ไม่อนุมัติ** ใน `ActionDialog`; ตีกลับและไม่อนุมัติต้องมีเหตุผล; อนุมัติแจ้งผู้ดูแลคลัง ผลทุกแบบแจ้งผู้ขอ
- ผู้ขอยกเลิกได้ขณะ `SUBMITTED`/`RETURNED`
- จ่าย (ผู้ดูแลคลัง, `FormDialog`): ต่อบรรทัดระบบเสนอล็อตแบบ **หมดอายุก่อนจ่ายก่อน (FEFO)** จากคลังหลัก (ไม่มีวันหมดอายุไว้ท้ายสุด, เท่ากันเรียงตามวันสร้างล็อต) ข้ามล็อตหมดอายุแล้ว เปลี่ยนล็อต/แบ่งหลายล็อตได้ จ่ายน้อยกว่าที่ขอได้ (รวมทั้ง 0) แต่ต้องใส่หมายเหตุ จ่ายเกินที่ขอไม่ได้ → `ISSUE_OUT` จากคลังหลัก + `ISSUE_IN` เข้าคลังย่อยต่อล็อตใน transaction เดียว → `ISSUED` แจ้งผู้ขอ. ยอดไม่พอ ณ ตอนบันทึก → 409 `INSUFFICIENT_STOCK` (ไม่ตัดบางส่วน)
- ใบที่ `ISSUED` แล้วยกเลิกไม่ได้ (ของผิดแก้ด้วยปรับยอดรอบ 2)

### 6. ตัดใช้ (ข้อ 6, 11)
- ปุ่มใหญ่ "ตัดใช้" เปิด `FormDialog`: คลังย่อย (เจ้าหน้าที่ที่มีงานเดียวเลือกให้อัตโนมัติ), วัสดุ (ค้นด้วยรหัส/ชื่อ แสดงยอดคงเหลือ), จำนวนหน่วยใช้, ประเภทการใช้ (ค่าเริ่มต้น "ตรวจผู้ป่วย"), วันที่ (ค่าเริ่มต้นวันนี้, ไม่เกินวันนี้, รอบ 2: ไม่อยู่ในเดือนที่ปิดงวด), หมายเหตุ. ล็อตเลือกอัตโนมัติแบบ FEFO แสดงให้เห็น และกด "เปลี่ยนล็อต" เพื่อเลือก/แบ่งเองได้
- ล็อตที่หมดอายุแล้ว (expiry_date < วันที่รายการ) ตัดใช้และจ่ายไม่ได้ → 409 `LOT_EXPIRED` (ต้องปรับยอดทิ้งในรอบ 2)
- ยกเลิก (`ActionDialog` + เหตุผล): ผู้บันทึกเองหรือผู้ดูแลคลัง → `USE_REVERSAL` คืนยอดเข้าล็อตเดิม สถานะ `REVERSED` แถวเดิมไม่ถูกลบ

### 7. ยอดคงเหลือและบัญชีเคลื่อนไหว
- ตารางต่อคลัง (ตัวเลือกคลัง; เจ้าหน้าที่เห็นเฉพาะงานตัวเอง): วัสดุ, คงเหลือ (หน่วยใช้ + เทียบหน่วยรับ เช่น "25 ขวด (2 กล่อง 5 ขวด)"), มูลค่า, ล็อตที่ใกล้หมดอายุที่สุด, ป้าย "ต่ำกว่าจุดสั่งซื้อ"; และมุมมอง "รวมทั้ง Lab"
- กดวัสดุ → รายล็อต + บัญชีเคลื่อนไหวตามช่วงวันที่ (ฟอร์มช่วงวันที่: เลือกวันเริ่มแล้ววันสิ้นสุดตั้งเป็นวันเดียวกันอัตโนมัติ ตามกฎฟอร์มของโปรเจกต์)

### 8. การแจ้งเตือนรอบ 1
outbox `notification.in_app` ต่อคนเท่านั้น (ใบขอเบิกส่ง/ตัดสิน/จ่าย, ยอดยกมาส่งรับรอง/ตัดสิน). payload มีเลขเอกสารและลิงก์ ไม่มีเหตุผลการตัดสิน. จำนวนรอเรื่องแสดงเป็น badge บนไทล์โมดูลตามกลไก badge เดิม.

## พฤติกรรมรอบ 2 (ตกลงแล้ว รอ plan แยก)

- **คำขอปรับยอด** (ข้อ 13): ผู้ดูแลคลังเลือกคลัง ล็อต จำนวน ± เหตุผล (หมดอายุ / ชำรุด / สูญหาย / นับไม่ตรง) → หัวหน้า Lab อนุมัติ/ไม่อนุมัติ → `ADJUSTMENT`. ลดได้ไม่เกินยอดคงเหลือ
- **ใบนับสต็อก**: ผู้ดูแลคลังเปิดใบนับต่อคลัง (snapshot ยอดตามระบบรายล็อต) กรอกยอดนับจริง (เพิ่มล็อตที่พบแต่ไม่อยู่ในระบบได้) → ส่วนต่างรวมเป็นคำขอปรับยอดชุดเดียว เหตุผล "นับไม่ตรง"; ถ้ามีรายการเคลื่อนไหวหลัง snapshot ระบบคิดส่วนต่างจากยอดตอน snapshot บวกรายการหลังนั้น
- **รายงานประจำเดือน** (ข้อ 7): ต่อคลังและรวมทั้ง Lab ต่อวัสดุ ยกมา | รับ/โอนเข้า | ใช้/โอนออก (แยกตามประเภทการใช้ได้) | ปรับยอด | คงเหลือ ทั้งจำนวนและมูลค่า คำนวณจาก `lab_movement` ตาม entry_date; พิมพ์ (print CSS) และส่งออก Excel (.xlsx ถ้าเพิ่ม dependency ได้ ไม่งั้น CSV UTF-8 BOM) ผ่าน audit `data.export`
- **ปิดงวด**: หัวหน้า Lab ปิดเดือนได้เมื่อเดือนก่อนหน้าปิดแล้วและไม่มีคำขอปรับยอดค้างในเดือนนั้น → `lab_period_close` (year_month, closed_by, closed_at) + snapshot ยอดปลายงวด; หลังปิด ทุกรายการที่ entry_date อยู่ในเดือนนั้นบันทึก/ยกเลิกไม่ได้ (409 `PERIOD_CLOSED`) ไม่มีการเปิดงวดใหม่ในรอบนี้
- **เตือน** (ข้อ 8): ต่ำกว่าจุดสั่งซื้อต่อคลัง, ใกล้หมดอายุภายใน `expiry_warn_days`, หมดอายุแล้วยังมียอด → การ์ดบนภาพรวม (เจ้าหน้าที่เห็นเฉพาะงานตัวเอง) + worker สรุปทุกเช้า 07:30 (เวลาไทย) ส่งกระดิ่ง + LINE ถึงหัวหน้า Lab และผู้ดูแลคลัง (ไม่ส่งถ้าไม่มีรายการ) ข้อความมีจำนวนรายการและลิงก์ ไม่มีรายละเอียดอื่น

## ความปลอดภัย
- API ทุกตัวตรวจสิทธิ์ฝั่ง server ผ่าน `LabAccess` ที่ประกอบจาก `AuthorizationService` (`lab.manage`) + `lab_member`; ไม่มี per-page manager check
- ไม่มีเหตุผลการตัดสิน/การยกเลิกใน URL, log, audit metadata, notification, outbox payload
- ยอดไม่ติดลบ: ตรวจใน transaction ด้วย `FOR UPDATE` + `CHECK (quantity >= 0)` บน `lab_lot_balance`

## นอกขอบเขต
ขอเบิกจากคลังพัสดุกลาง/สั่งซื้อ, ฉลาก QR/สแกน, แนบไฟล์ใบส่งของ, ต้นทุนต่อ test และเชื่อม LIS/HOSxP, คลังของหน่วยงานอื่นนอก Lab, เปิดงวดที่ปิดแล้ว, หน่วยทศนิยม

## การทดสอบ

## กฎ popup และฟอร์มของโปรเจกต์
ทุก popup ใช้ `FormDialog`/`ActionDialog` ปิดได้จากปุ่มเท่านั้น. ฟอร์มช่วงวันที่ในบัญชีเคลื่อนไหว (และรายงานรอบ 2) เลือกวันเริ่มแล้วตั้งวันสิ้นสุด = วันเริ่มอัตโนมัติ.

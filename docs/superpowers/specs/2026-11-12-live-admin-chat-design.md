# แชตกับผู้ดูแลระบบแบบ live — design

วันที่ 2026-11-12 · ผู้ขอ: wasan — "ปรับระบบ Chat ให้เป็นแบบ live chat เตือนอัตโนมัติไม่ต้อง refresh"

## ปัญหาเดิม

หน้าต่างที่เปิดอยู่ดึงข้อความทุก 5 วินาที แต่ตัวเลขบนปุ่มอัปเดตทุก 30 วินาที และไม่มีอะไรเตือนเมื่อมีข้อความใหม่ ผู้ใช้จึงต้องกดเปิดดูเองหรือ refresh

## พฤติกรรมใหม่

- ทุกหน้าที่เข้าสู่ระบบแล้วเปิดการเชื่อมต่อ live หนึ่งเส้น (Server-Sent Events, `GET /api/support-chat/stream`) ซึ่งส่งสถานะแชตทันทีที่เปลี่ยน
  - สถานะ = `{ unread, lastMessageAt, conversationId }` ไม่มีเนื้อความ
  - ส่งในเซิร์ฟเวอร์เดียวกัน: ปลุกทุกสายทันที (ไม่เกินเสี้ยววินาที) ส่วนเซิร์ฟเวอร์อื่น/ทางสำรอง: ตรวจทุก 2 วินาที
  - ping ทุก 15 วินาทีกัน proxy ตัดสาย, ปิดสายทุก 5 นาทีให้เบราว์เซอร์ต่อใหม่ (ตรวจ session ใหม่), เบราว์เซอร์ต่อใหม่เองหลัง 3 วินาทีถ้าหลุด
- เมื่อสถานะเปลี่ยน: ตัวเลขบนปุ่มอัปเดตทันที, หน้าต่างแชตที่เปิดอยู่และกล่องข้อความของผู้ดูแลระบบโหลดข้อความใหม่ทันที
- **เตือนอัตโนมัติ** เมื่อมีข้อความใหม่ถึงเรา (ตัวเลขยังไม่อ่านเพิ่มขึ้น):
  - ผู้ใช้ทั่วไป: หน้าต่างแชตกับผู้ดูแลระบบเปิดขึ้นเอง (ถ้าย่ออยู่ก็ขยาย)
  - ผู้ดูแลระบบ: หน้าต่างของบทสนทนาที่มีข้อความใหม่เปิดขึ้นเอง (ยังใช้กฎสูงสุด 3 หน้าต่าง)
  - เสียงเตือนสั้น ๆ (ถ้าเบราว์เซอร์อนุญาต) และชื่อแท็บกะพริบ "(n) ข้อความใหม่" จนกว่าจะกลับมาที่แท็บ
  - ปุ่มแชตเต้นเบา ๆ (ปิดเมื่อผู้ใช้ตั้งลดการเคลื่อนไหว)
- ถ้า EventSource ใช้ไม่ได้ ยังดึงตัวเลขทุก 30 วินาทีแบบเดิมเป็นทางสำรอง; หน้าต่างที่เปิดอยู่ดึงทุก 15 วินาทีเป็นทางสำรอง (เดิม 5)
- หน้าต่างแชตยังปิดได้จากปุ่มของมันเท่านั้น

## ความปลอดภัย

สายสตรีมใช้ session เดียวกับ API อื่น ส่งเฉพาะสถานะของผู้ที่เข้าสู่ระบบ ไม่มีเนื้อความหรือชื่อผู้ใช้; ผู้ใช้ทั่วไปเห็นเฉพาะบทสนทนาของตัวเอง
Caddy ไม่บีบอัด path สตรีม (บีบอัดทำให้ event ค้างใน buffer); nginx อ่าน `X-Accel-Buffering: no`

# ระบบการลา Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A live "การลา" module where every บุคลากร files ใบลา that go up the command chain, with automatic day counting, balances, cancellations, bulk approval, a team calendar and HR settings.

**Architecture:**
- A ใบลา is a central **คำขอ** with `moduleCode: 'leave'`, plus a `leave_request` detail row, both written in one transaction.
- Pure modules hold the rules: `leave-days.ts` for counting, fiscal year, overlap and warnings, and `leave-balance.ts` for entitlement and carry.
- Database services: `LeaveSettingsService`, `LeaveService` for writes, `LeaveQueries` for reads, and the balance CSV.
- Next.js routes and pages under `/leave`, with access checked on the server.

**Tech Stack:** pnpm monorepo, TypeScript, zod 4, mysql2 on MariaDB 11.8, Drizzle schema, Next.js App Router, Vitest, Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-26-leave-design.md`

## Global Constraints

- **Migration:** `packages/db/migrations/0011_leave.sql`, additive, listed after 0010 in `packages/db/src/migrate.ts`. The Drizzle schema lives in the new `packages/db/src/schema/leave.ts`, exported like the other schema files. Add a 0011 row to `docs/integration/modules.md` and the new tables to `infra/backup/restore-verify.sh`.
- **Leave type seeds:** fixed UUIDs `00000000-0000-4000-9000-00000000000N`. All five have `approval_target` `HOSPITAL`, `is_active` 1 and sort order N.
  - N=1 `SICK` ลาป่วย: `WORKING_DAYS`, attachment from 30 days.
  - N=2 `PERSONAL` ลากิจส่วนตัว: `WORKING_DAYS`.
  - N=3 `VACATION` ลาพักผ่อน: `WORKING_DAYS`.
  - N=4 `MATERNITY` ลาคลอดบุตร: `CALENDAR_DAYS`.
  - N=5 `PATERNITY` ลาไปช่วยภริยาคลอดบุตร: `WORKING_DAYS`.
- **Entitlement seeds,** only for `CIVIL_SERVANT` (employment type id `00000000-0000-4000-8000-000000000001`):
  - SICK 60.
  - PERSONAL 45, first year 15.
  - VACATION 10, cap 20, cap after 10 years 30, minimum service 6 months.
  - MATERNITY 90.
  - PATERNITY 15.
- **`leave_setting`:** one row, `id = 1`, `min_working_days_per_month = 15`.
- **Fiscal year:** a Buddhist-era integer. The year runs 1 Oct to 30 Sep, so `fiscalYearOf('2026-10-01') === 2570` and `fiscalYearOf('2026-09-30') === 2569`.
- **Day amounts:** multiples of 0.5, stored as `DECIMAL(5,1)` and read with `CAST(col AS CHAR)` then `Number()`. Dates are SQL `DATE`, read with `DATE_FORMAT(col, '%Y-%m-%d')`. Store UTC and display Asia/Bangkok.
- **Permission:** `leave.manage`, added to `permissionSchema`, granted to `hr-manager`. `requiresDataOwner('leave.manage')` is true, and the hospital-wide check is `canActHospitalWide(subject, 'leave.manage', 'hr')`.
- **Audit actions:**
  - `leave.request.submitted`, `leave.request.resubmitted`, `leave.cancel_days.submitted`.
  - `leave.type.create`, `leave.type.update`, `leave.entitlement.set`, `leave.entitlement.delete`.
  - `leave.holiday.create`, `leave.holiday.update`, `leave.holiday.delete`, `leave.setting.update`, `leave.balance.import`.
  - Metadata may hold ids, type codes, dates, day counts, `fiscalYear`, `changedFields` and `rowsChanged`. It never holds reason, contact or attachment content. Add `leaveTypeCode`, `days`, `fiscalYear`, `rowsChanged`, `startDate` and `endDate` to the redact allowlist.
- **Notifications:** `moduleCode: 'leave'`, `targetPath: '/leave/requests/<requestId>'`, and the existing generic Thai subjects.
- **Module:** the `leave` registry entry becomes live with sections. `/leave` uses `ModuleIndex`, so the first section is a real page at `/leave/mine`, not `/leave` (a ruling, recorded in the ledger).
- **Copy:** all UI copy is Thai in `packages/i18n/src/th.ts`. The terms ใบลา, ประเภทการลา, สิทธิ์การลา, ปีงบประมาณ, วันลาสะสม, ยอดวันลาคงเหลือ, ขอยกเลิกวันลา and วันทำการขั้นต่ำต่อเดือน are added to `CONTEXT.md`.
- **Attachments:** the attachment upload route still returns `object_storage_not_configured` (503), so files cannot be attached yet. This round keeps the nullable `attachment_id` column. `ATTACHMENT_REQUIRED` is not enforced. When a ใบลา reaches `attachment_required_from_days`, it carries `medicalCertificateRequired: true`. The form tells the person to hand the certificate to HR, and the ใบลา page shows the flag to approvers. This is a ruling on the spec, recorded in the ledger and reported to wasan.

## Review Focus

1. **Shared request routes:** a ใบลา resubmitted through `/api/requests/[id]/resubmission`, or a `leave` คำขอ created through `POST /api/requests`, would skip every leave check. Both must answer 400 `leave_request_route`. Pinned in Task 5.
2. **Concurrent submits:** two submissions of VACATION at the same moment for a person with 3 days left, each asking 2 days. Exactly one succeeds and the other gets `INSUFFICIENT_BALANCE`. Pinned in Task 7.
3. **Hidden ใบลา:** a person who is neither on the approval steps nor `leave.manage` opens `/leave/requests/<id>` of someone else and gets not found. The calendar response carries no `leaveTypeId`, `reason` or `contact` keys at all. Pinned in Task 9.
4. **Half days on one date:** a morning ใบลา and an afternoon ใบลา on the same date do not overlap. A second morning does overlap. A one-day ใบลา with start `AFTERNOON` and end `MORNING` is invalid input. Pinned in Task 1 and Task 2.
5. **Bulk approve:** an approve-many call that includes the actor's own ใบลา, one the actor is not assigned to, and an already approved one. The others are approved, and each failure gets its own error with no rollback of the successes. Pinned in Task 8.

### Task 2: Day counting, fiscal year, overlap and monthly warnings

**Files:**
- Create: `packages/core/src/leave/leave-days.ts` and `leave-days.test.ts`

**Interfaces:**
- Consumes: `DayRange`, `LeaveCounting` and `LeaveWarning` from Task 1.
- Produces:
  - `fiscalYearOf(date: string): number` and `fiscalYearRange(fiscalYear: number): { start: string; end: string }`.
  - `leaveUnits(range: DayRange, counting: LeaveCounting, holidays: ReadonlySet<string>): string[]`. Each unit is `'YYYY-MM-DD:AM'` or `'YYYY-MM-DD:PM'`. Working-day counting skips Saturday, Sunday and holidays. A start `AFTERNOON` drops the first day's AM, and an end `MORNING` drops the last day's PM.
  - `countLeaveDays(range, counting, holidays): number`, which is `units.length / 2`.
  - `subtractUnits(units: string[], removed: string[]): string[]`.
  - `workingDaysInMonth(month: string, holidays): number`.
  - `monthWarnings(input: { units: string[]; otherUnits: string[]; holidays: ReadonlySet<string>; minimum: number }): LeaveWarning[]`. For each month that `units` touches, it counts the working-day units of `units ∪ otherUnits` in that month, divides by 2, and reports when `workingDaysInMonth − that < minimum`. Months are sorted.

### Task 3: Balance rules

**Files:**
- Create: `packages/core/src/leave/leave-balance.ts` and `leave-balance.test.ts`

**Interfaces:**
- Consumes: `LeaveBalance` from Task 1 and `fiscalYearRange` from Task 2.
- Produces:
  - `interface Entitlement { daysPerYear: number; firstYearDays: number | null; maxAccumulatedDays: number | null; maxAccumulatedDaysAfter10Years: number | null; minServiceMonths: number }`
  - `serviceMonths(appointedOn: string, on: string): number` counts whole months.
  - `computeBalance(input: { carries: boolean; entitlement: Entitlement; fiscalYear: number; appointedOn: string | null; opening: { carriedDays: number; usedDays: number } | null; approvedDays: number; cancelledDays: number; pendingDays: number; previousYearRemaining: number | null }): LeaveBalance`
    - `entitled` is `firstYearDays` when the fiscal year contains `appointedOn` and it is set, otherwise `daysPerYear`.
    - `carried` is `opening.carriedDays` when there is an opening row. Otherwise, when `carries`, it is `min(max(previousYearRemaining ?? 0, 0), cap − daysPerYear)`. The cap is the after-10-years value once 10 years have passed at the fiscal year start, and the regular cap before that. A missing cap means 0. It is never negative.
    - `used = (opening?.usedDays ?? 0) + approvedDays − cancelledDays`.
    - `remaining = entitled + carried − used − pendingDays`.

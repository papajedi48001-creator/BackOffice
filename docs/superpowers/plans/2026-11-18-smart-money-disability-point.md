# Smart Money round 4: Point ฟื้นฟูผู้พิการ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Move the legacy `modules/disability_point` pages into BackOffice at `/money/disability` and
`/money/disability/files`, with the same numbers and screens.

**Architecture:** As round 3. The browser reads CSV (TIS-620/UTF-8) or Excel with SheetJS and posts the header plus ≤ 1,500
rows per request. The server parses with a TypeScript port of `DpParser` and upserts one row per เลขที่อ้างอิง in
`money_dp_record` (record JSON encrypted with the national-ID key). The dashboard loads every record and computes in the
browser with a TypeScript port of `dp-core.js`.

**Tech Stack:** Next.js App Router, zod, MariaDB + Drizzle, vitest, `@e965/xlsx@0.20.3` (browser only), `NationalIdProtector`.

**Spec:** `docs/superpowers/specs/2026-11-18-smart-money-disability-point-design.md`. Legacy: `modules/disability_point/*`,
`tests/disability_point/*`.

## Global Constraints
- Upload and delete need `money.manage`, checked on the server before the body is read. Viewing needs the `disability` page tick or manage.
- Body ≤ 2 MB; ≤ 1,501 rows of ≤ 80 cells (strings ≤ 1,000 chars, finite numbers, booleans, null); fileName ≤ 255; uploadId UUID.
- Records stored encrypted; no เลขบัตร, name, HN, ref or money in URL, log or audit.
- Audit: `money.dp.upload` {rows, added, updated}, `money.dp.remove` {fy, records}.
- Client components import only types from `@backoffice/core`. Popups close only from their buttons. Dates entered with
  `ThaiDateInput`, shown as `13 พ.ย. 2569`.

## Review Focus
1. A file without "เลขที่อ้างอิง"/"ชื่อบริการฟื้นฟู" or missing a required column is refused with the legacy Thai message.
2. Re-uploading the same ref replaces it (and moves ปีงบ if the date moved); two parts of one file make one log row.
3. Without the national-ID keys, upload is refused and nothing is stored; the stored column never holds a เลขบัตร in clear.
4. A member without the `disability` tick gets 403 from GET; a non-manager gets 403 from POST/DELETE without the body being read.
5. Parser output equals legacy PHP output for the legacy test rows (fixtures generated by running `DpParser`).

## Rulings during execution
- Ruling: `ref` VARCHAR(100), and a ref over 100 characters is refused. Real refs are 8 digits. If this is wrong, a longer ref is refused instead of being stored.
- Ruling: `record_ciphertext` is MEDIUMTEXT, because 29 Thai fields of up to 1,000 characters could overflow TEXT.
- Ruling: `money_dp_upload.uploaded_at` is DATETIME(6), so that "ไฟล์ล่าสุด" stays in order when two uploads land in the same second.
- Ruling: ปีงบ "ปรับปรุงเมื่อ" = MAX(uploaded_at) of the ปีงบ's records. Legacy also touched a ปีงบ that only lost moved refs. The cost is that this time can be older than legacy in that one case.
- Ruling: clicking a trend bar is done through buttons in a collapsible "ตารางแนวโน้ม", because the CSS `BarChart` has no click.
- Ruling: the browser limit is 50 MB per file and 200 MB per zip. Legacy had no limit of its own.
- Final: fixed ปีงบ outside 2500–2700 (stored but undeletable). Test `refuses a date whose ปีงบ cannot be stored or deleted` RED→GREEN, with the legacy message "ปีงบไม่ถูกต้อง: N".
- Final: fixed one unreadable file failing the whole zip. Test `reports an unreadable file inside a .zip` RED→GREEN.
- Final: fixed the รายการ page not resetting on filter change. Test `goes back to the first page of รายการ` RED→GREEN.
- Final: deferred minors:

  - `~$` files are listed where legacy dropped them silently.

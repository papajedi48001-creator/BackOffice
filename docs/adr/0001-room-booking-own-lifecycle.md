# 0001 การจองห้องประชุมมีสถานะของตัวเอง ไม่ใช้คำขอและสายอนุมัติกลาง

**Status:** accepted
**Date:** 2026-10-21

## Context

R0 มี **คำขอ** และ **สายอนุมัติ** กลาง (`request`, `approval_step`) ที่มอบแต่ละขั้นให้บุคลากรรายบุคคลตาม **ภาพผู้อนุมัติ ณ เวลายื่น** และมีผลการพิจารณา อนุมัติ ไม่อนุมัติ ส่งกลับแก้ไข

การจองห้องประชุมต้องการ: ผู้อนุมัติเป็นกลุ่มตามบทบาท (ใครในกลุ่มก็พิจารณาได้), ไม่มีการส่งกลับแก้ไข, การยกเลิกพร้อมเหตุผลโดยผู้จองหรือผู้ดูแล, การคืนวันที่เหลือของการจองหลายวัน และการกันช่วงเวลาตั้งแต่ยื่น ซึ่งคำขอกลางไม่รองรับ

## Decision

การจองห้องประชุมเก็บสถานะ ประวัติ และเลขอ้างอิงของตนเอง (`room_booking`, `room_booking_day`, `room_booking_history`, เลข `RB-ปี-ลำดับ`) และใช้ส่วนกลางที่เหมาะสมร่วมกันเท่านั้น: บันทึกการตรวจสอบ, outbox, การแจ้งเตือนในระบบ, session และบทบาท

## Consequences

- กติกาการจองเปลี่ยนได้โดยไม่กระทบคำขอของโมดูลอื่น
- หน้าจอ "คำขอ" กลางจะไม่แสดงการจองห้อง ผู้ใช้ดูที่เมนูห้องประชุม
- การแจ้งเตือนต้องลิงก์ไปหน้าที่ไม่ใช่คำขอ จึงเพิ่ม `notification.target_path`
- ถ้าภายหลังคำขอกลางรองรับผู้อนุมัติแบบกลุ่มและการยกเลิก อาจย้ายมาใช้ได้ แต่ต้องย้ายข้อมูลเดิม
- โมดูลรถยนต์ (R3) ใช้แนวเดียวกันได้ แต่ยังไม่แยกส่วนกลาง "การจองทรัพยากร" จนกว่าจะมีโมดูลที่สองจริง
